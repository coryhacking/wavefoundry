## Rationale

Every framework Python process recompiles the framework modules it imports from source, every time. Entry scripts and most library modules set `sys.dont_write_bytecode = True` at module scope (`docs_lint.py`, `indexer.py`, `server.py`, `wf_cli.py` and 18 more, censused below), while 28 of the 44 non-test scripts that run as processes set nothing, and the test runner adds `-B` and `PYTHONDONTWRITEBYTECODE=1` to every worker (`run_tests._run_file`). A profiling run on 2026-10-07 found compilation was about 45% of each docs-lint subprocess. A prototype that pre-compiled into a per-user prefix outside the repository cut `test_docs_lint` from about 229 s to about 166 s and `test_indexer` from about 170 s to about 128 s. The same cost is paid at runtime by every hook invocation, every `wf` command, every MCP server start and every setup/index child.

The current per-module flag also fails at its own job. It takes effect only after the module that sets it has run, so anything imported earlier writes `__pycache__` into the source tree. On 2026-10-07 the working tree held 17 `cpython-314` files in `.wavefoundry/framework/scripts/__pycache__/` (among them `venv_bootstrap`, `cli_stdio`, `indexer`, `runtime_lock`) and three in `scripts/wf_server/__pycache__/`. All were written at 08:15 to 08:16 that day. The rendered hook preamble `HOOK_BOOTSTRAP` (`render_platform_surfaces.py`) imports `venv_bootstrap` with bytecode writes still on, which accounts for at least `venv_bootstrap.cpython-314.pyc` (`inferred`: the full set of writers has not been traced).

Brief: the goal is faster framework processes for operators and agents, and for the test suite, with no `__pycache__` in source trees. The approach is a project-local bytecode prefix under `.wavefoundry/`, flushed whenever the framework version changes. The deliverable is framework code, rendered surfaces, seed and docs updates, and tests. Exclusions: no change to the stdlib or third-party packages and no new runtime dependency. Success means framework processes write bytecode only under `.wavefoundry/cache/pycache/`, start faster, never execute stale or foreign bytecode across an upgrade, and the cache never leaks into git, the pack, the indexes, the scanners or the test receipt.

## Requirements

1. A new stdlib-only module `bytecode_cache.py` in `.wavefoundry/framework/scripts/` owns the policy. It derives the cache directory from its own location only: when its directory is `<root>/.wavefoundry/framework/scripts`, the cache is `<root>/.wavefoundry/cache/pycache`. It never uses `--root`, the current directory or any environment variable to choose the location. When the scripts directory does not sit at that layout (a scratch copy in a test, for example), caching stays off, which is today's behavior.
2. `bytecode_cache.configure()` is idempotent and does the following in order. (a) It refuses the cache, leaving `sys.dont_write_bytecode = True` and no prefix (and clearing any prefix the interpreter took from an inherited `PYTHONPYCACHEPREFIX` that names this cache), when `.wavefoundry/cache` or `.wavefoundry/cache/pycache` exists and is a symlink or, on Windows, a junction or other reparse point. Detection uses `os.lstat`, plus `st_file_attributes & FILE_ATTRIBUTE_REPARSE_POINT` on Windows because `Path.is_junction` needs Python 3.12 and the floor is 3.11. The refusal runs first, so a read-only process never reads through a linked cache. (b) If the interpreter started with writes disabled (`sys.flags.dont_write_bytecode`, from `-B` or `PYTHONDONTWRITEBYTECODE`), it keeps a prefix inherited from the parent runner (Requirement 7) or otherwise sets the derived prefix, for reads only, and enables no writes and no flush. The one exception is a top-level `run_tests.py` run (Requirement 7): there the runner, not the interpreter flag, decides, so a documented `python3 -B run_tests.py` run still flushes. (c) It runs the version-stamp flush (Requirement 5). (d) It sets `sys.pycache_prefix` and `sys.dont_write_bytecode = False`. It does not export `PYTHONPYCACHEPREFIX` into `os.environ`: every framework script run as a process configures itself (Requirement 3), so inheritance is not needed, and an exported variable would reach non-framework children (sensor commands through `sensor_runner`, target product test runs, git and its hooks, uv) and make product Python write into `.wavefoundry/cache/pycache`. Only `run_tests.py` passes the variable, explicitly, to its own workers, warm-up and profile child (Requirement 7). Any `OSError` leaves caching off and is never raised to the caller.
3. Rule for the call sites, which is the set governing this change (coordinator decision: no in-tree bytecode anywhere): every non-test framework script that runs as a process, meaning it has a `__main__` entry or a framework subprocess argv names it, is an entry point, whether or not it sets the flag today; and every non-test module that assigns `sys.dont_write_bytecode = True` at module scope is converted. Entry points set `sys.dont_write_bytecode = True` before importing `bytecode_cache` and then call `bytecode_cache.configure()`, so neither `bytecode_cache` nor anything imported before it is written next to its source. Library modules, imported by other code, replace the unconditional assignment with a guard that disables writes only when no prefix is active. Library modules therefore never turn writes on themselves and no longer turn them back off after an entry enabled them. Exception: `upgrade_bundle.py` and `upgrade_bridge_bootstrap.py` also run as zip-root members of the release upgrade zipapp (`build_pack.build_upgrade_bundle`) and as a standalone copied bridge file, where `bytecode_cache` is not importable, so an unconditional import would break every release upgrade. These two set `sys.dont_write_bytecode = True` before their imports and do not import `bytecode_cache` (or import it only inside `try`/`except ImportError`); the census test accepts that form for them. The census below lists the sites at HEAD `404e4950` as evidence. The rule, not the table, governs, and a census test (Requirement 10) derives the set from the tree.
4. `HOOK_BOOTSTRAP` in `render_platform_surfaces.py` sets `sys.dont_write_bytecode = True` before `import bytecode_cache` (today it never sets the flag, so `bytecode_cache`'s own bytecode would land beside its source), then calls `configure()` (fail-safe, inside `try`) after inserting the scripts directory on `sys.path` and before importing `venv_bootstrap`. All hook files rendered from it are regenerated. The session-start hook (`claude_session_start_source`) keeps its own `sys.dont_write_bytecode = True` and does not cache: its contract is report-only and it must run on an older `python3`. The hook launchers in `.claude/settings.json` and other host configs, `.wavefoundry/bin/wf`, `wf.cmd` and the MCP registrations (`.mcp.json` and the `render_agent_surfaces` MCP args) pass no `-B` today and need no change, because configuration happens in-process.
5. Flush on upgrade uses a version stamp, so it also works on the installing upgrade. `configure()` compares the bytes of `.wavefoundry/framework/VERSION` (which carries a per-build suffix, for example `1.29.0+pukn`) with a stamp file inside the cache directory. On a mismatch or a missing stamp it flushes, then writes the stamp. The flush renames the cache directory to a unique sibling (`pycache.stale-<pid>-<random>`) and removes it with `shutil.rmtree`, which is symlink-attack resistant on POSIX (`shutil.rmtree.avoids_symlink_attacks` is `True` on this workstation's Python 3.14) and removes a link instead of descending into it. A symlink inside the cache is unlinked, never followed, and the removal never leaves `.wavefoundry/cache/`. Links at intermediate mirror components are in the same trust domain as the cache and are handled by the same removal. If the rename fails (Windows open handles, a concurrent flusher), caching stays off for that process and the next process retries. The old upgrade runner extracts and the first new-code framework process flushes, so no change to the old runner is needed. The transition-run note says so explicitly.
6. The framework test runner `run_tests.py` configures the cache in `main()` only, never at import time. `lifecycle_gate_support` imports `run_tests` in-process for the close gate (its docstring lists five restored interpreter-state channels), and an import-time prefix from a foreign `--root` would make a sixth, unrestored channel.
7. `run_tests.main()` warms the cache in a subprocess routed through `_run_tree_kill`, with a census row in `tests/test_tree_kill_routing.py`. The warm-up runs `compileall` over the framework scripts directory and the `stdlib`, `purelib` and `platlib` paths of the runner interpreter and of `$PYTHON` when that is set. Workers keep `-B` and `PYTHONDONTWRITEBYTECODE=1` (read-only) and receive `PYTHONPYCACHEPREFIX`. Read-only workers mean scratch modules created under the temp directory are never written into the cache. Once a prefix is set, Python ignores the installation's own `__pycache__`, so a read-only process with a cold prefix would recompile the standard library. Executed on 2026-10-07: importing six stdlib modules took 0.04 s without a prefix and 0.15 s with an empty prefix under `-B`. The warm-up is therefore required, not optional, whenever a prefix is in use. `run_tests.py` passes `PYTHONPYCACHEPREFIX` to its workers, warm-up and profile child, and runs the warm-up, only when the parent's `configure()` left a prefix active; when `configure()` refused or found no layout, workers get no prefix variable and no warm-up runs. The child discriminator is an inherited `PYTHONPYCACHEPREFIX`, set only by a parent `run_tests`: a runner that inherits one is a child, which does no warm-up and no temp-mirror cleanup and reuses the prefix read-only. A top-level run with no inherited prefix, including a documented `python3 -B run_tests.py` run, still configures, flushes and warms; the warm-up subprocess is launched without `-B`, so it writes regardless of the parent's `-B`. Each top-level run also removes the cache's mirrors of `tempfile.gettempdir()` in both its given and its resolved spelling (on macOS `/var/folders/...` and `/private/var/folders/...`; contained, no-follow), because tests that drop `PYTHONDONTWRITEBYTECODE` can still write scratch mirrors (the prototype's cache held 280 KB under `var/folders` after one run). A second-profile run (`_profile_run_in`) reuses the parent's warm prefix read-only (coordinator decision): `_child_runner_env` passes the parent's `PYTHONPYCACHEPREFIX`, the child keeps that inherited prefix under its `PYTHONDONTWRITEBYTECODE=1` (Requirement 2 (b)), and the child's `main()` does no warm-up and derives no prefix of its own, so no second cold cache (about 175 MB) is built per profile run.
8. Exclusions: `.wavefoundry/cache/` is added to the managed gitignore block `_GITIGNORE_BLOCK` and its seed-050 source, to `machine_authority.HARDCODED_EXCLUDE_PREFIXES` (used by the index walk and the secrets non-git fallback), and to `reconcile_scan._STATIC_EXCLUDED_DIRS`. The following already exclude it and are verified by test, not edited: the receipt hash `_hash_inputs` (walks `.wavefoundry/framework/` only), `build_pack.collect_files` (walks the framework directory and drops `.pyc`), the project index blanket `PROJECT_INDEX_EXCLUDE_PREFIXES` (`.wavefoundry/`, whose self-host re-includes are only `.wavefoundry/framework/scripts` and `dashboard`), the refresh filters that skip `.pyc`, the repository-state guard `repo_state_snapshot` (git-ignored paths are outside it), docs-lint (walks `docs/` and defers to `.gitignore`) and the dashboard file activity (git status).
9. Stale-bytecode safety: Python validates a timestamp `.pyc` by source mtime (whole seconds) and size. The upgrade extracts with `zipfile.extractall`, which stamps extraction time (executed on 2026-10-07: a 2020 member extracted with the current time), while `unzip` restores archive mtimes. An extraction that restores mtimes could therefore pair a same-size edit with a stale `.pyc`. The version-stamp flush covers every packaged upgrade or reinstall, because `VERSION` differs per build. The bridge install restores the old `VERSION` bytes, but `extractall` stamps fresh mtimes on what it extracts and the feature upgrade that follows changes `VERSION`, so stale `.pyc` is still prevented on that path. Hash-based validation (`--check-hash-based-pycs`) is not used. The MCP reload path `_discard_reloaded_bytecode` (`server.py`) unlinks `module.__spec__.cached`, which points into the prefix once one is set, and must keep working. With writes on, `importlib.reload(server_impl)` would write a fresh `.pyc` into the prefix, `_bytecode_cache_absent` would then return `False`, and `wf_reload_mcp` would silently stop recording runner identity (the existing reload tests run under `-B`, so they cannot see this). The reload therefore runs with `sys.dont_write_bytecode = True`, restored to its prior value afterwards.
10. Tests (all in the framework suite): a derived census of module-scope `sys.dont_write_bytecode` assignments in non-test scripts, failing when a site neither calls `configure()` nor uses the guard. Subprocess tests over a scratch install laid out as `<tmp>/.wavefoundry/framework/scripts`, with `PYTHONDONTWRITEBYTECODE` and any inherited `PYTHONPYCACHEPREFIX` removed from the child environment (otherwise a scratch child started by a `run_tests` worker would write into the real cache before `configure()` runs), cover `docs_lint.py`, `wf_cli.py docs-lint`, `server.py --dry-run` and one rendered hook body. Flush, refusal and opt-out tests, the `run_tests` import non-mutation test and the exclusion tests named in the ACs complete the set.
11. Documentation: the seed-050 **Framework Script Hygiene Rule** text, a seed-160 upgrade step that replaces the prior seed-050 hygiene paragraph in a target's `AGENTS.md` with the new one when it matches the prior wording exactly (seed 160 today only backfills the section when it is missing, so upgraded targets would keep the old wording; any other wording is project-authored and is reported, not rewritten), the AGENTS.md **Framework Script Hygiene** section, `docs/architecture/testing-architecture.md`, `docs/contributing/build-and-verification.md`, `.wavefoundry/framework/docs/lint-exclusions.md` and `docs/architecture/threat-model.md` describe the cache location, the flush, the `PYTHONDONTWRITEBYTECODE` opt-out and platform behavior. They replace the "clean `__pycache__` by hand" instructions with a statement that stray in-tree `__pycache__` is a defect. Existing `python3 -B ... run_tests.py` commands stay valid and are left alone.

## Scope

**Problem statement:** framework processes recompile every framework module on every start, and the per-module flag meant to keep source trees clean still leaks `__pycache__` into `.wavefoundry/framework/scripts/`.

**In scope:**

- `bytecode_cache.py` (new), every module-scope bytecode site under the rule in Requirement 3, `HOOK_BOOTSTRAP` and the re-rendered hooks, and `run_tests.py` (configure in `main`, warm-up, worker environment, temp-mirror cleanup).
- Exclusion additions in `render_platform_surfaces._GITIGNORE_BLOCK`, seed 050's gitignore block, `machine_authority.py` and `reconcile_scan.py`.
- Seed 050 and AGENTS.md hygiene text, the seed-160 exact-text replacement step, and the docs named in Requirement 11.
- The wave's final CHANGELOG pass under the existing `## [1.29.0]` heading (the bullet texts recorded by `200v1` and `200xx` plus this change's) and the final AGENTS.md edit.
- Tests named in Requirement 10 and the ACs.

**Out of scope:**

- The roughly 100 `-B` flags and `PYTHONDONTWRITEBYTECODE` assignments in test files under `scripts/tests/`. Their children stay read-only; only `run_tests`' own workers, warm-up and profile child receive the prefix, so other `-B` children get it only when started by such a worker with its environment intact, and otherwise run uncached.
- `-I` probes (`setup_readiness`, `venv_bootstrap`, `upgrade_protocol`). `-I` ignores `PYTHON*` variables, so they are unaffected.
- Removing pre-existing stray `__pycache__` outside the framework directory (`.claude/hooks/__pycache__`, `docs/waves/*/evidence/__pycache__`). `_clean_pycache` keeps removing in-tree caches under the framework directory before each test run.
- Cache size caps or eviction beyond the version flush and the temp-mirror cleanup.
- Hash-based `.pyc` validation.

## Platform Behavior

- **Linux and macOS:** the prefix mirrors absolute source paths (macOS resolves `/tmp` to `/private/tmp`, observed). Writes are atomic through importlib's temp-and-replace. The symlink refusal uses `os.lstat`.
- **Windows (native):** the prefix mirrors `C:\...` as `<prefix>\...` with the drive letter dropped (CPython's mapping, mirrored by `bytecode_cache.mirror_dir`; `inferred`, not executed here), so the same path on two drives shares a mirror and timestamp validation still applies. Deep site-packages paths can pass the 260-character limit when long paths are disabled. importlib ignores the failed write and the process compiles from source, so the cost is speed, never correctness (`inferred`). A replace over a `.pyc` another process holds open can fail with `PermissionError`, which importlib also ignores. Junctions and reparse points are refused through `st_file_attributes`. There is no ownership or mode check. The prototype's `os.getuid` and group/other-writable check does not apply to NTFS, and the cache is in the same trust domain as the scripts (see Decision Log). A flush rename that fails because of open handles leaves caching off for that process. `wf.cmd` is unchanged.
- **WSL2:** a checkout used from both Windows and WSL gets two disjoint mirror subtrees (the drive-less Windows path, for example `Users\...`, and `mnt/c/...`), so no cross-OS bytecode is shared. A cache on `/mnt/c` works but is slower over 9p (`inferred`).
