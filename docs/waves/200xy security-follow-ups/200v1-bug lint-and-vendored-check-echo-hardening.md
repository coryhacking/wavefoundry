## Rationale

Wave `1zxo0` made the lifecycle tools read a member change doc only as a regular file inside its folder and inside the repository (`lifecycle_gate_support._read_member_doc_bytes`), and its delivery repairs gave docs-lint's wave-owned-doc loop an `lstat` guard. Its delivery re-verification, and wave `1zyb2`'s, left gaps of the same two classes: a reader that follows a linked record document (so outside content can reach messages or be processed as a record) or blocks on a non-regular one, and a message that echoes untrusted text to a terminal or an audit payload. This change closes those gaps so the member-doc rule holds for every docs-lint and single-id change-lookup reader of a record document, and the vendored-script check never echoes README or server text it has not validated.

Brief: goal is one consistent read rule for record documents across docs-lint and the single-id change lookup, plus echo-free vendored-check messages; consumers are operators running docs-lint and `wf_audit` and maintainers running the network verifier; success is that a linked or non-regular record document is never followed or opened by any of these readers and no message carries unvalidated README or server text. Public repository: defects are described by class only.

Code-grounded facts (verified against HEAD `404e4950` on 2026-10-07; no framework script differs from HEAD in the working tree):

- Docs-lint record reads outside the guarded loop: `docs_constants_validators.check_wave_scaffolding_integrity` reads each wave's `wave.md` and every `wave_dir.glob("*.md")` document with `Path.read_text` (no `lstat`). Its messages interpolate the document's `Wave:` value and the wave record's unbracketed signoff value, and its `except OSError` lets a `UnicodeDecodeError` escape the pass; reading through the record reader (Requirement 2) fixes both, since the reader decodes with `errors="replace"` and a refused document is never parsed. `wave_validators.check_migration_edges` walks the waves root with `rglob("*.md")` and reads each file through `helpers.read_text`, which calls `Path.read_text` after a following `stat`.
- Discovery that follows links: `helpers.iter_markdown_docs` and `wave_validators._wave_folder_docs` admit entries with `Path.is_file()`, so every pass fed by them (`_collect_wave_state`, the metadata and link validators through `cli`) reads a linked record document too. The same holds for `wave_validators.check_plan_filenames` (plans-root `iterdir` plus `is_file()` plus `read_text`), `core_validators.check_scaffold_declares_nothing` (`is_file()` plus `read_text` on `review_policy.SCAFFOLD_DOCS`, which lies under the plans root) and `wave_validators.check_orphan_wave_ledgers` (`wave_md.is_file()` plus `read_text`). Wave folders come from `record_paths.discover_wave_dirs`, whose `_has_wave_md` uses a following `is_file()`, so a linked `wave.md` still makes its folder a wave for every caller (25 non-test call sites outside docs-lint as well).
- The docs-lint secrets pass (`cli` calls `secrets_validators.check_hardcoded_secrets` in both the full and `--changed` modes, `record_only=True`) builds its file set from the git changed and untracked set (`_get_changed_files`) or the whole tree (`_get_all_files`), each admitted with a following `is_file()`, and `scan_file_raw` reads each file with `read_bytes` and `read_text`. So a changed or untracked linked record document is followed there as well. Docs-lint runs it serially (`max_workers=1`).
- Only the wave-owned-doc loop in `wave_validators` (an `lstat` before its read) and `wave_validators.member_status_drift` (through `_read_member_doc_bytes`) apply the rule. No `.md` entry under `docs/waves/` or `docs/plans/` in this repository is a link or a non-regular file today (`find` run 2026-10-07), so the rule changes no result here.
- Single-id change lookup: `server_impl._resolve_change_doc_matches` walks each change source with `rglob("*.md")` and reads every candidate through `_read_repo_text_checked`, which refuses only a runtime-lock target (`_refuse_runtime_lock_target`, judged on the resolved path) and otherwise calls `read_text`. So a linked change doc's target content is returned, and a non-regular candidate named `*.md` blocks the lookup. Wave `1zxo0` named this as a follow-up and its repairs did not route it. Its callers are `get_change`, `wf_get_change_response`, `_resolve_unique_change_doc` (defined, never called: no reference in the scripts or tests), `wf_add_change_response` (which then probes the entry's own `source_path` through `_read_member_doc_text` before any move) and the `resource_change` resource. `tests/test_code_reader_lock_guard.py` pins the lock behavior: `ResourceLockTargetTests.test_slug_resources` expects `# Refused` from `resource_change` for a change doc symlinked to a runtime lock, and `CheckedReaderCensusTests` requires `_resolve_change_doc_matches` to reference `_read_repo_text_checked` or `_refuse_runtime_lock_target`. `_read_member_doc_bytes` refuses a symlink as `not a regular file` before its lock-identity check (which covers hard links only, `st_nlink > 1`), so calling it alone would turn the symlinked-lock case into an ordinary unreadable match and break both tests.
- Vendored-script check (`vendored_integrity.py`, shipped; `verify_vendored_scripts.py`, source repository only): `parse_readme` raises `registry row N: duplicate package` and `row N: package has no registry row`, which echo nothing today, but no test exercises either message (no match for either string under `tests/`), so a mutant that adds the package name survives. `_FILE_ROW_RE` and `_REGISTRY_ROW_RE` capture `package`, `source` and `url` as any non-backtick text, so C0 and C1 control characters other than line breaks survive `splitlines()`; `verify_vendored_scripts.verify` prints `package`, `entry.url` and `f.source` raw. `_row_path_problem` refuses C0 and C1 control characters but not Unicode format characters (category `Cf`, which includes bidirectional controls and zero-width characters), and `_row_label` echoes any path that passes it, so such a path reaches `wf_audit` `data.vendored_scripts.problems` through `server_impl._audit_vendored_scripts`.
- Server-supplied text in the verifier: the refused-redirect message is built at two sites, `_RegistryRedirectHandler.redirect_request` (the `newurl` value) and `default_fetch` (the `final_url` value), and `verify` prints the `FetchRefused` text. `default_fetch` wraps any `OSError` or `ValueError` as `FetchError(f"{type(exc).__name__}: {exc}")` and `verify` prints `download failed: {exc}`; an `HTTPError`'s text carries the server's reason phrase, so server text reaches the terminal there too.

## Requirements

1. **Record-document set.** A record document is any `*.md` entry that lies, lexically, under the resolved waves root or the resolved plans root (`helpers.resolve_record_roots`). The set is derived by that rule, not by a list of passes. Non-`.md` files under the record roots (review ledgers, evidence files) keep today's handling.
2. **One lint read path.** `wave_lint_lib/helpers.py` gains one reader for record documents that reads through `lifecycle_gate_support._read_member_doc_bytes(path.parent, path, root=<lint root>)` and decodes as `helpers.read_text` does today (UTF-8, `errors="replace"`). Its read cache is keyed on the entry's `lstat` identity and the opened file's `fstat` identity (`st_dev`, `st_ino`, `st_mtime_ns`, `st_size`), never on a following `stat`. Every docs-lint read of a record document uses it, including the secrets pass's read of a record document (`scan_file_raw`). The implementer runs and records a census (predicate: a call of `read_text(`, `.read_text(`, `.read_bytes(`, `open(` or `os.open(` in `wave_lint_lib/` or `docs_lint.py` whose path can lie under a record root) and routes each hit. The import stays function-local where a module-level import would cycle, as in `member_status_drift`.
3. **Enumeration does not follow.** The rule covers every docs-lint enumeration of entries under a record root: an entry is yielded as a record document only when `lstat` shows a regular file. Named sites (from the census above; the rule, not this list, governs): `helpers.iter_markdown_docs`, `wave_validators._wave_folder_docs`, the `check_wave_scaffolding_integrity` glob, the `check_migration_edges` walk, the `check_plan_filenames` plans-root `iterdir`, `core_validators.check_scaffold_declares_nothing`, the `check_orphan_wave_ledgers` `wave_md.is_file()` probe, and the secrets pass's file set (`secrets_validators._get_changed_files` and `_get_all_files`) for record documents; a linked or non-regular record document the file-set filter drops is surfaced through the secrets scanner's existing `_record_scan_skip` channel (Requirement 4), never silently. `record_paths.discover_wave_dirs` stays unchanged for its other callers (it is shared framework-wide); docs-lint treats a discovered folder whose `wave.md` is not an `lstat` regular file as holding a refused record document, reports that entry once (Requirement 4) and skips the folder in every per-wave pass, so the orphan-ledger pass does not report it a second time. `wave_validators.archive_readability_findings` is excluded: archived records are history read under the archive profile, and it reports a read failure by exception class only. A record-root `*.md` entry that is a link or not a regular file is never opened by any docs-lint pass.
4. **One report per refused document.** Docs-lint reports each refused record document once as a blocking error naming the entry's own repository-relative path and a cause class (a link or special file, outside its folder or the repository, over the size cap). Mechanism: the record reader and the non-following enumerations record each refusal in a per-run registry in `helpers` (keyed on the entry's repository-relative path), cleared by `read_text_cache_clear` at the start of each run; passes skip a refused entry without reporting it, and `cli` emits one error per registry entry after the passes, in both the full run and the incremental `--changed` run (the post-edit hook path). The message never contains the link target, any byte of the target's content, or any value read from it. The existing wave-owned-doc message (change id only) is folded into the registry, so the same entry is never reported twice. A refusal raised at read time (an entry swapped after discovery) is recorded the same way and never raises out of docs-lint or blocks. In the secrets scanner, which also runs outside docs-lint (the standalone scanner and the close gate), `secrets_validators.scan_file_raw` surfaces a record-reader refusal through the existing `_record_scan_skip` channel (its process-safe stderr line plus `_SCANNER_SKIPS`) with the repository-relative path and a path-free cause class; the file-set filter surfaces a dropped linked record document the same way; neither outcome is cached as a clean scan; and the scanner's `MAX_FILE_BYTES` (5 MiB) guard stays ahead of the record read.
5. **Single-id change lookup.** `_resolve_change_doc_matches` first calls `_refuse_runtime_lock_target(root, p)` (so a symlinked runtime lock keeps `refused: True`, as today), then reads the candidate through `_read_member_doc_bytes(p.parent, p, root=root)`; its lock-identity refusal of a hard-linked lock is also returned with `refused: True`. Any other refused candidate that matches the token is returned as today's unreadable match (`content` empty, `read_error` a cause class with no path). Its existence probe does not follow links. The response shape for readable documents is unchanged. Each caller's outcome: `get_change` returns `None` for a refused match, as for any unreadable one; `wf_get_change_response` returns the unreadable match; `wf_add_change_response` refuses before any move or write through its existing `_read_member_doc_text` probe of the entry's own `source_path`; `resource_change` returns `# Refused` for a lock and `# Unreadable Change` with the path-free cause otherwise. The uncalled `_resolve_unique_change_doc` is deleted.
6. **Vendored README fields.** `vendored_integrity.parse_readme` refuses, with `ReadmeError` naming the table, the row number and the field name only, a file-table or registry row whose `package`, `source` or `url` contains a C0 or C1 control character or a Unicode format character (category `Cf`). `_row_path_problem` refuses Unicode format characters with the existing control-character class, so `_row_label` names such a row by number.
7. **Network verifier output.** After Requirement 6, every README-derived field `verify_vendored_scripts.verify` prints has passed the field check. Both refused-redirect messages (`redirect_request` and `default_fetch`) name the refusal class only, with no redirect target. `default_fetch` builds `FetchError` from the exception class name only, so `download failed:` never prints a server reason phrase or other exception text.
8. **Pinned registry messages.** Tests pin the exact text of `registry row N: duplicate package` and `row N: package has no registry row`, and assert neither contains the package value.
9. **Docs.** `docs/architecture/cross-cutting-concerns.md` (the `lifecycle_gate_support` Shared Utilities bullet) states that docs-lint reads every record document through the rule, replacing "Docs-lint is only partly covered ... (a follow-up)". `docs/specs/mcp-tool-surface.md` (the `wf_get_change` entry) states that single-id lookups apply the same read rule. One CHANGELOG security bullet names the classes (docs-lint and single-id change lookups no longer follow or block on linked or special record documents; vendored-script table fields with control or format characters are refused rather than printed, and the network verifier no longer prints server-supplied text), with no reproduction steps or sample values. The bullet text is recorded in this change's Progress Log; change `1zyv1` (the wave's last change) writes it under the existing `## [1.29.0]` heading in its final CHANGELOG pass.

## Scope

**Problem statement:** some readers of wave and plan documents still follow links and open special files, and the vendored-script check can print unvalidated README or server text.

**In scope:**

- Requirements 1 to 9 and tests for each.

**Out of scope:**

- Docs-lint reads outside the record roots (the general `docs/` tree and the entry files keep their link-following policy), and non-`.md` files under the record roots.
- `record_paths.discover_wave_dirs` and its non-docs-lint callers (lifecycle tools, server, indexer), which keep following a linked `wave.md`.
- `wave_validators.archive_readability_findings` (Requirement 3).
- The archived change and wave lookups (`_archived_change_matches`, `_archived_wave_matches`), which already refuse links and non-regular files through `_archive_file_ok`.
- `docs_gardener`, which reads and stamps record documents through links: a named follow-up for a later wave.
- The upgrade preview's traceback text, which is output-only and not part of either echo class here.

## Platform Behavior

- **macOS and Linux:** the member-doc rule's `O_NOFOLLOW|O_NONBLOCK` open with an `fstat` identity check applies to every record read, so a FIFO never blocks and a link is refused at open as well as at `lstat`.
- **Windows:** no `O_NOFOLLOW` and no FIFOs; the `lstat` regular-file check plus resolved containment stands alone, and the helper reads with the builtin `open`, as `_read_member_doc_bytes` documents. Symbolic links and junctions report as non-regular to `lstat` and are refused. The window between `lstat` and open is the documented limit. The AC-3 spy covers both the `os.open` and the builtin `open` paths, so it runs on every platform.
- **WSL2:** Linux semantics on the distribution filesystem; on a DrvFs mount the same `lstat` and open checks run, and Windows-created links appear as links or as non-regular entries, so they are refused.
- The vendored field check is pure string handling and identical on every platform; `unicodedata` is stdlib.
