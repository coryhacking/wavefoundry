# Memory archival and retention lifecycle

## Rationale

Agent memory is now the durable destination for project learning. Superseded,
rejected, and no-longer-operational records remain historically valuable, but
keeping their full bodies in the active memory directory and normal index makes
the working corpus noisier as a repository ages. Retain that history as
version-controlled records while moving it out of default retrieval, leaving
compact active pointers for high-value discovery.

## Requirements

1. A reconciled record may be archived only through an explicit, typed archival
   decision. The archived body retains its memory ID, evidence, targets,
   supersession links, and an `archived` status with an archive reason and date.
2. Archival moves the canonical body by a rename into
   `docs/agents/memory/archive/`; it must not implement the move as a
   copy/delete sequence.
3. Active memory retains a compact, project-visible pointer for each archived
   record containing the stable ID, title, kind, targets, searchable keywords,
   evidence summary, successor when present, and archive location.
4. Normal memory search, briefings, action-time advisories, graph extraction,
   and docs semantic retrieval exclude archived bodies. Normal search may return
   an active pointer; an explicit archive/history request may resolve the body.
5. Decisions, operator preferences, and still-relevant fragile-file records are
   not archive-eligible from age alone. Superseded records, rejected candidates,
   and stale tactical records have explicit eligibility rules and review cues.
6. Archive moves, pointer changes, and index/cache invalidation are serialized
   through the existing memory fence and are state-derived, restart-safe, and
   idempotent. A rerun after an interruption must converge without orphaning
   references or duplicating a record.
7. Existing source-event dispositions remain authoritative: archived records
   must not be regenerated by proposal, historical backfill, or close-time
   capture.
8. Install and upgrade preserve a valid project if archival work is pending or
   interrupted; they must not publish a mixed active/archive index state.

## Scope

**Problem statement:** current status filtering hides stale history from normal
memory tools, but full records remain in the active directory and ordinary docs
index. There is no physical archive, pointer surface, retention policy, or
archive-safe migration path.

**In scope:**

- Memory schema, parser/lint, reconcile/archive MCP contract, and active pointer
  representation.
- Archive directory traversal rules; exclusion of archived bodies from default
  docs indexing, graph extraction, advisories, and search.
- Explicit archive/history retrieval, retention review cues, and archive counts.
- State-derived rename migration, memory-state fencing, cache/index coherence,
  and upgrade/backfill integration.
- Tests covering rename semantics, interruption/retry, source-disposition
  suppression, index exclusion, pointers, and explicit history retrieval.
- Architecture, tool-surface, lifecycle-prompt, and memory-schema documentation.

**Out of scope:**

- Changing retrieval relevance or decay formulas; owned by
  `1t7ab-enh adaptive-memory-freshness-and-retrieval`.
- Automatic archival without an explicit reconciliation decision.
- Remote, hosted, or object-store archival.
- Deleting memory history or reviving per-wave journals as an archive format.

## Acceptance Criteria

- [ ] AC-1: An archive action renames a valid memory body to the archive
  directory, preserves its ID and provenance, marks it `archived`, and creates
  one valid active pointer; a second invocation is a no-op.
- [ ] AC-2: Default memory search, briefs, action-time advisories, semantic
  indexing, and graph extraction never expose an archived body; an explicit
  history/archive query can return its body through the documented contract.
- [ ] AC-3: The active pointer is searchable by ID, title, targets, and keywords
  and resolves to the archived record without duplicating its body in the active
  corpus.
- [ ] AC-4: Eligibility protects decisions, operator preferences, and relevant
  fragile-file records from age-only archival; every eligible archival category
  requires an explicit reason and reconciliation decision.
- [ ] AC-5: Forced interruption at each archive transition and restart/retry
  converges to exactly one active-or-archived body, one correct pointer state,
  and no stranded live references or store rows.
- [ ] AC-6: Proposal, backfill, and close-time capture do not regenerate an
  archived source event; upgrade/setup preserve a resumable, non-mixed state.
- [ ] AC-7: Documentation, full framework tests, and docs validation are clean.

## Risks

| Risk | Mitigation |
| --- | --- |
| Interrupted move strands references | State-derived recovery, fence, and crash-window tests |
| Archive bodies still surface through docs index | Explicit exclusion tests across docs, graph, and advisory paths |
| Retention harms durable knowledge | Protected kinds plus explicit review and history retrieval |
| Upgrade publishes mixed state | Reuse resumable memory backfill/index-publication discipline |
