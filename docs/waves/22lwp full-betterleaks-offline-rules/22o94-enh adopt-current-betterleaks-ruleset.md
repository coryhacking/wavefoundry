## Rationale

The operator wants the full newer Betterleaks ruleset as a follow-up to [22o91](../22o93%20scanner-rule-corrections/22o91-bug%20scanner-rule-compatibility-and-sourcegraph-noise.md). That wave repairs project overrides, updates Sourcegraph and supplies an import inspector. It deliberately does not adopt the complete upstream configuration.

Use immutable [Betterleaks commit 8f376ff9c31ed5309ac448fe601c5dd21b376155](https://github.com/betterleaks/betterleaks/blob/8f376ff9c31ed5309ac448fe601c5dd21b376155/config/betterleaks.toml) as the candidate, not a moving latest URL. Actual parsed inventories contain 474 candidate rules versus 280 in the current local configuration. The earlier ID comparison found 199 additions and five removals; removals and changed common rules need deliberate treatment, not a union that silently retains obsolete detection.

The 22o93 candidate inspector completed a bounded pass over all 474 entries: 17 filters failed parsing and 123 filter-function references were unsupported. Those are occurrences, not distinct functions. It also reported 882 unsupported field occurrences, one unsupported filter variable, one regex compilation warning and one rule without a regex. Some fields are inert action metadata; a missing regex can represent a composite rule. These counts identify investigation work, not 1,025 detector defects or proof that the remaining rules work. The current 280-rule configuration also reports unsupported metadata. A blanket file replacement cannot establish useful coverage.

Further source-grounded investigation identifies a format transition: the pinned release is v2.0.0-rc.7 and uses Expr, not the local CEL-style subset. Its own Expr v1.17.8 parser successfully parsed all 430 offline expressions (428 rule filters and two global expressions), representing 51 unique expressions and 18 function names. The rules include 37 component-bearing definitions, 44 standalone-report suppressions, three explicit capture selectors and one path-only PKCS#12 rule. A public offline-API prototype precompiled all 474 rules and passed four synthetic cases on macOS ARM64 without Go on its runtime PATH. The helper is approximately 11.6 MB; a Windows AMD64 cross-build succeeded but was not executed. These are feasibility observations, not implementation or platform qualification.

The operator selected a Python implementation of the pinned offline semantics, without a shipped Go helper or new runtime dependency. The operator reports no custom detection rules in Waveforge or the other current projects. Preserve the existing legacy CEL engine for explicitly legacy inputs; select the upstream Expr profile explicitly and diagnose unsupported profile combinations. Do not infer arbitrary legacy-to-Expr compatibility from the absence of current custom rules.

A temporary stdlib-only tokenizer prototype matched the pinned upstream tokenizer on 2,006 deterministic samples with zero mismatches in approximately 0.156 seconds. This establishes feasibility for the sampled Unicode, whitespace and repeated-character cases; it does not qualify the complete engine, all Unicode versions or production cost. The actual upstream AST inventory confirms 430 expressions, 51 unique expressions and 18 function names. String length counts Unicode runes while slices and match offsets use UTF-8 bytes; token-efficiency checks use the pinned cl100k ranks and dictionary. These semantics require explicit fixtures rather than Python-string approximations.

## Product Intent

Give teams broader, current secret detection without silently weakening filters, extraction, local-only operation or existing project policy. This extends the adopted vision's Horizon 1 dependable foundation; it does not create another acceptance program or alter the vision. AC-2 through AC-5 establish actual detection and safe delivery rather than merely an increased rule count.

### Qualification budget

Use the same machine and interpreter for baseline `b33211eb` and candidate. Freeze deterministic 1 MiB normal-source and adversarial workloads before measurement, including near-matches, repeated identifiers and composite fan-out; preserve the corpus recipe and case identities. After one warm-up, measure three runs of each workload. Candidate median elapsed time must be at most the larger of five times baseline median or 10 seconds; every completed run must stay within 120 seconds and 512 MiB peak resident memory. Report startup and asset-load cost separately from warmed evaluation. These are local qualification bounds, not a universal performance claim.

Run separate pathological/oversized controls through the real worker boundary. They may return explicit incompleteness within 120 seconds rather than complete; they must not publish a clean result, suppress pending work or start an unbounded fallback. A measurement harness killing a hung scanner is a failed production-boundary test, not a passing incomplete result. If ordinary workloads exceed the budget or any required rule remains unqualified, return the concrete gap for operator decision instead of silently dropping coverage or widening the budget.
