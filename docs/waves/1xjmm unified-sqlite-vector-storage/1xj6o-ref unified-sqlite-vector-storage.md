# Convert Local Vector Storage to Unified SQLite

## Rationale

Give destination projects a smaller, simpler local index by replacing LanceDB with SQLite + sqlite-vec, storing chunk text once and committing vectors, FTS and associated metadata together. Preserve search quality, supported filters, incremental indexing and recoverability. Deliver conversion through standard `wf_upgrade`, including verified cleanup; do not require operators to stage a replacement runner or manually export their index.

This is the production implementation follow-up to [evaluation 1xhdh](../1xhbo%20lancedb-038-evaluation/1xhdh-maint%20evaluate-lancedb-038-upgrade.md). Its reviewed current-corpus prototype preserved tested results, reduced steady database files from 248.04 to 164.31 MiB, and removed a demonstrated split-commit window. It did not qualify live indexer integration, destination migration, all platforms, scale limits or uninterrupted reader availability. Those become explicit gates here. This separate change avoids treating an evaluation approval as implementation approval.

[ADR 1xjmn](../../architecture/decisions/1xjmn-adr%20unified-sqlite-vector-storage.md) records the proposed architecture and database location. Keep it synchronized with the final G1 runtime/schema decision and measured operating envelope before acceptance.

## Requirements

1. Use the existing project-local `.wavefoundry/index/index-state.sqlite` as the one authoritative SQLite file for both docs and code canonical chunks, float32 vectors, external-content FTS and existing index-state consumers. Share internal integer keys while retaining public chunk IDs scoped by docs/code layer. Keep docs/code FTS populations separate so BM25 statistics do not change. Store canonical text once; vector rows contain no duplicate text. Preserve optional payload fields, including tags, section breadcrumbs and line ranges.
2. Retain embedding model, dimension, cosine metric, chunking, hashes, pre-limit filters, candidate counts, fusion, reranker and top-K. No quantization, ANN change or model change accompanies conversion. Bind regression expectations to the corrected static CPU reranker from 1xj6n; inherit exactly its three recorded exceptions against the older baseline, with no additional quality waiver.
3. Precompute embeddings outside the write transaction. One logical writer commits related chunk/FTS/vector/registry/digest/file/layer changes with `BEGIN IMMEDIATE`; check attempt, filesystem/content identity and model/chunker versions before applying prepared work. File hashes remain file hashes, distinct from chunk hashes. Invalidate and republish lexical statistics correctly. Preserve source reconciliation and global publication fences for graph and other data outside this transaction.
4. Use the measured float32 scalar scan, selective metadata indexes and 256 MiB mmap/default cache as the starting configuration. Keep WAL, NORMAL data commits, FULL publication fences, foreign keys, bounded busy handling and default 4 KiB pages. Establish incremental auto-vacuum on creation/migration; retain reusable pages, passive checkpoint normally, and bound idle reclamation. No routine full VACUUM or forced TRUNCATE checkpoint. Select result hydration from measured plans; one-SQL hydration was slower in the prototype.
5. Select and pin one supported SQLite binding/runtime plus sqlite-vec through Gate 1. Verify the linked runtime has the documented WAL fix; extension installation alone is not a SQLite upgrade. APSW was an evaluation vehicle, not a preselected production dependency. All connections participating in the shared file must use the qualified connection policy; audit any remaining bindings and checkpoint writers.
6. Route fresh installs, existing projects, retries and explicit rebuilds through the canonical setup/index/upgrade entrypoints. Fresh installs require no LanceDB. Existing projects load LanceDB only for bounded source conversion/recovery, not normal SQLite queries. Avoid a permanent dual-backend runtime or dual writes.
7. Standard `wf_upgrade` orchestrates migration, publication verification, required restart/reconnect and cleanup. Preserve existing docs, memory-validation and publication gates. A storage-format failure must retain actionable recovery state and block destructive cleanup, even where ordinary historical index failures previously allowed framework cleanup to finish.
8. Cleanup removes only proven Wavefoundry-owned obsolete artifacts after all migration gates pass. Project content, unrelated databases/caches, model caches, user environments and other projects' dependencies are protected. Report reclaimed bytes and any retained dependency/artifact with its reason; never declare cleanup complete when a required removal failed.

## Scope

**In scope:** runtime selection and packaging support; unified schema and transactional indexer/query adapters; health/dashboard/optimization/evaluation consumers; standard upgrade conversion, resumable recovery, cleanup and downgrade instructions; focused regression and destination fixtures; architecture and external-use documentation.

**Out of scope:** hosted databases; SQLiteAI sqlite-vector (operator licensing deferral); quantization; new search behavior; permanent backend configurability; graph/memory database consolidation; deleting an entire `.wavefoundry/index` tree; automatic release publication or a release-version assignment. Operator authorized preparation, review and implementation after evaluation closure. Disposable install/upgrade/package fixtures are part of the gated verification; real destination upgrades, release publication, conversion-wave closure and commit remain separate operator actions.

## G1 Concrete Contract

Operator authorized local implementation through local package testing, followed by target testing on
other platforms. Preserve the established macOS ARM/Intel, Linux x64/ARM, WSL2 and native Windows
contracts and Python 3.11 minimum; do not claim unexecuted targets passed or add an OS-based runtime
ban. No bridge release and no manual replacement-runner staging.

- **Runtime:** pin `apsw==3.53.4.0` (private SQLite 3.53.4 amalgamation) and `sqlite-vec==0.1.9`.
  `sqlite_runtime.py` owns explicit native connection creation/loading, error classification, coherent
  backup and transaction helpers. No global sqlite3 monkeypatch, stdlib fallback for this file or
  second binding to it. Separate graph/memory files retain their current bindings. Native APSW
  transaction/affected-row/backup semantics get direct tests; busy/I/O errors never trigger deletion.
- **Schema:** version 7 at existing `index-state.sqlite`; `chunks_docs`/`chunks_code` own integer
  rowids, layer-unique public IDs, canonical text and complete metadata. `vectors_docs`/`vectors_code`
  reference those rowids with FP32 BLOBs, content/model identity and cascade deletion. External-content
  `fts_docs`/`fts_code` retain the exact eight columns/tokenizer and separate BM25 populations. Triggers
  maintain FTS; canonical rows hold text once. Existing auxiliary tables and publication fences survive.
  Unknown/newer schema or corrupt canonical data is refused with recovery guidance, never silently reset.
- **Storage API:** `sqlite_vector_store.py` exposes bounded `dense_rows`, `payload_rows`, layer availability/
  counts and transaction-local row mutations. Preserve existing filter grammar and pre-limit semantics;
  bind values and allow only named layers/columns. Do not emulate Arrow, pandas or an ANN builder.
  Indexer owns `BEGIN IMMEDIATE` and related canonical/vector/registry/digest/file/layer writes on the
  same connection; embeddings stay outside. FTS/digest repair cannot destroy canonical vectors.
- **Upgrade:** `sqlite_storage_migration.py` owns `.wavefoundry/index/sqlite-migration.json`, bound to
  project, source identity, target code, stage/snapshot identity and known host identities. States:
  `restart_required`, `quiesced`, `staged`, `validated`, `cutover_pending`, `published`, `verified`,
  `cleanup_pending`, `complete`. Atomic fsynced receipt writes record progress; the existing global
  publication fence remains authority. Incoming archive `post_extract` can arm a fatal restart pause
  before format changes. The newly installed ordinary runner reads/restores receipt-bound checkpoint
  state before generic stale-lock clearing, and preserves docs/memory gates. Full host-shutdown
  confirmation follows existing framework compatibility practice, backed by strict existing locks and
  refusal while an identified old host lives. Confirmation is an operator assertion, not universal
  process enumeration; an ordinary CLI shell parent is not automatically an old MCP host.
- **Boundaries:** no format mutation before quiescence, no legacy deletion before new-process
  verification. Setup/index/state-open/publication/alternate-upgrade/cleanup entries check unresolved
  migration. The receipt survives old-finalizer checkpoint deletion and selects retry recovery. Source
  vectors stream through a lazy pinned Lance reader; full packaged conversion and interruption cases
  qualify the implemented machinery at G4/G5, not before that machinery can be written.

Local runtime execution passed on Python 3.11.13 and 3.13.5. Archived 1.16.2+pipa/1.22.0+pomi
boundary probes and a new-process receipt-first prototype exercised abort, checkpoint loss/recovery,
missing confirmation, live old host, correct resume, wrong target and a guard-removal mutant. Full
sources/results/provenance are in `runtime-qualification.json`; these prove local prerequisites, not
full migration or foreign-platform delivery. Retain the existing upgrade floor and compatibility
patterns; the oldest available local archive does not redefine supported versions.

## Standard Upgrade and Recovery Path

The state names below describe required behavior; use the existing upgrade checkpoint plus one durable, versioned migration receipt under `.wavefoundry/index/` for storage identity/retry evidence. G1 freezes the supported source-release/protocol floor and representative first-hop fixtures, receipt/path/schema names, and a transition/recovery table naming executing code version, live processes, allowed writers, authoritative files, durable evidence and permitted retry at every boundary. Its earliest disposable public-entrypoint fixture must prove an old coordinator cannot release publication fencing through historical cleanup after an incomplete migration. Do not create competing publication authorities or interpret directory presence as success.

1. **Discover and preflight.** Normal `wf_upgrade` preflight detects legacy stores, already-migrated state, first install, missing/partial layers and interrupted conversion. Inspect actual schema/backend/model identities, source generation, corruption/readability, runtime availability, permissions and disk needed for original stores, a coherent rollback snapshot, staged SQLite, WAL and safety headroom. Dry-run reports actions/bytes and writes nothing. No manual newer-runner staging or capability-grep detour. Conversion cannot piggyback on a chunker bump that unnecessarily re-embeds every compatible vector.
2. **Prepare runtime and quiesce.** Standard setup installs the qualified SQLite runtime and extension through the tool environment. Preserve access to the compatible Lance reader until conversion/rollback completes. Fence new work and stop/drain every writer, monitor and database-owning process before taking source snapshots or replacing files. A new marker alone cannot stop older processes that ignore it. Gate 1 must prove either cooperative process exclusion or a structured restart-required pause/resume through ordinary upgrade flow, including the invoking old MCP process. Never rely on hot reload to replace an already-loaded native binding.
3. **Snapshot and stage.** Record exact source table versions, IDs, hashes, dimensions/model/chunker identity and the coherent SQLite state generation. Use SQLite backup/checkpoint-aware operations, not copying a live main DB while ignoring WAL. Stream compatible Lance vectors in bounded batches into an unpublished staging SQLite file on the same filesystem. Copy and preserve unrelated existing state tables; do not collapse the graph or memory authority into this migration. Retain the original Lance stores and coherent pre-conversion state until cleanup is eligible.
4. **Reconcile and validate.** Reuse compatible vectors with zero embedding calls for unchanged chunks; re-embed only incompatible/changed chunks through the existing pipeline. Apply filesystem changes since the snapshot and handle deleted/ignored/moved files. Validate transfer equality before reconciliation, then validate the desired final keyed set after reconciliation so legitimate source changes are not mistaken for corruption. Verify chunks, vectors, FTS MATCH/external-content integrity, registry/digests, file hashes, model identity and all intended layers. Unreadable/corrupt source is an explicit repair/rebuild-required result; no silent empty-store success or source deletion. A full rebuild uses the canonical recovery path and its normal model/download policy.
5. **Cut over and publish.** Close/drain handles, preserve a rollback copy and make the staged database authoritative under the existing publication lock. File replacement, receipt transitions and the global epoch CAS are not one SQL transaction: define recovery for each boundary with fsync/atomic replacement and platform-correct WAL handling. Do not replace a main DB beneath live WAL/SHM handles. Only a verified target generation can be reported ready. Retain the global FULL attempt-ID fence for graph/other work; conversion does not invent whole-index atomicity across separate databases.
6. **Verify from new processes.** Reload/reconnect or restart as required by the chosen binding and stale-host proof. Run docs/code lexical and semantic search, representative public filters, file edit/delete/reinsert, health/dashboard counts and reopen checks using the newly installed code. No Lance reads, writes or auto-install are allowed on normal SQLite operation. Persist a verification receipt bound to project, migration ID, source identity, schema/runtime, published generation and tested code version. A later run must validate the current compatible SQLite state rather than blindly require an obsolete exact generation or trust an old pass.
7. **Clean up through `wf_upgrade(phase='cleanup')`.** Only after G5, remove obsolete project-owned `.wavefoundry/index/docs.lance/`, `.wavefoundry/index/code.lance/` and `.wavefoundry/index/__manifest/`, plus any additional legacy vector artifacts identified by the source inventory, unpublished staging debris and the migration rollback snapshot. Use exact owned paths and receipt-bound identities; refuse symlinks/path escapes, unknown provenance or open handles. Never glob-delete `.lance` anywhere in the project or wipe the whole index. Preserve canonical SQLite and other project state. The `__manifest` folder is part of the legacy-store inventory and must not be left behind after both vector stores are retired; G1 verifies its ownership and absence of remaining consumers. In this repository the operator-referenced code/docs folders are `code.lance/` and `docs.lance/`; project source folders such as `<project-root>/docs/` are never cleanup targets. Keep a compact completion receipt so a second cleanup is a proven no-op; tolerate interruption by recording remaining work and retrying idempotently. A cleanup error reports failure/remaining bytes and retains recovery state instead of claiming a clean upgrade.
8. **Reconcile dependencies.** Remove LanceDB from fresh-install/runtime requirements and eliminate obsolete auto-install, handle, corruption-workaround and maintenance paths from normal SQLite code. Retain only a lazy migration reader for supported legacy upgrades. Existing environments are often shared across projects: uninstall LanceDB or an exclusive transitive dependency only when framework ownership, the supported consumer inventory and dependency graph prove none still needs it and no old process holds it. Do not introduce a new global consumer-registry subsystem solely to uninstall packages. Unknown/unregistered consumers or a user-managed environment mean retain with an explicit reason, not broad `pip uninstall`. Do not remove shared numpy/model/MCP dependencies or pyarrow merely because LanceDB used it. If future legacy conversion needs the reader, standard setup can provision its pinned migration-only dependency; fresh SQLite operation must not require it.

**Retry and rollback contract:** before authority switch, the original coherent stores remain recoverable; retry validates the receipt/source identity and reuses or discards only unpublished staging. Between file replacement and verified publication, recovery either finishes the exact recorded candidate or restores the coherent old stores plus their compatible framework/runtime before reopening clients. Never pair an old framework with the new SQLite format, or restore only vectors while retaining newer metadata. After cutover but before cleanup, automatic rollback is permitted only while no newer successful writes would be lost; otherwise preserve/reconcile those changes or rebuild from current sources explicitly. After successful cleanup the retained Lance snapshot no longer exists: downgrade requires reinstalling the older supported framework/runtime and rebuilding its derived index from current project files. This is a documented rebuild, not an instant reversible format downgrade.
