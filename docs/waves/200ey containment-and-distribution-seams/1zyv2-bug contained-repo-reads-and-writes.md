# Contained Repository Reads and Writes

Change ID: `1zyv2-bug contained-repo-reads-and-writes`
Change Status: `implemented`
Owner: framework-operator
Status: planned
Last verified: 2026-10-07
Wave: 200ey containment-and-distribution-seams

## Rationale

The Waveforge maintainers reported, through the private channel, that several framework readers and writers of repository files are not contained to the repository. The operator verified each class against HEAD `404e4950` plus wave `200xy`'s working tree. The session handoff reader and writers, the prompt reader and the read-only MCP resources follow links, including a linked directory, so content outside the repository can be served or overwritten (high). The platform-surface renderer writes and marks files executable through a final link, and the install-log read is uncapped and follows links (medium). The prompt-move migrations read through a resolved path in a separate step from their check, and they do not keep the moved file's mode (low). The runtime-lock refusal on these paths judges a resolved name and then opens the path in a second step (partly fixed by `200v1` for the single-id change lookup only).

Wave `1zxo0` already wrote the right rule once: `lifecycle_gate_support._read_member_doc_bytes` reads a file only when `lstat` shows a regular file, its resolved path lies inside the repository, it is not a hard link to a runtime lock, and on POSIX the `O_NOFOLLOW` open's `fstat` identity matches the `lstat` identity, with a size cap. Wave `200xy` (change `200v1`) extended that rule to docs-lint and the single-id change lookup. The remaining readers and writers each do it their own way or not at all, and that divergence is where the reported classes live.

Brief: goal is one shared contained read and write primitive, used by every reported reader and writer, so the containment rule has one owner. Consumers are operators and agents (handoff, prompts, resources), installers (rendered surfaces, install log) and distribution maintainers (prompt moves). Success: no covered path reads or writes outside the repository through a link, opens a special file, reads unbounded input, or changes a file mode through a link; every refusal is path-free; ordinary files and links that stay inside the repository behave as today. Public repository: defects are described by class only, with no reproduction detail; the reporters are credited as the Waveforge maintainers.

Code-grounded facts (verified against HEAD `b97fa4ba` on 2026-10-07; wave `200xy` is committed as `2ebce84e` and `204jj` as `b97fa4ba`):

- Handoff: `wf_server/edit_gate_handlers.wf_get_handoff_response` reads through `server_impl._read_repo_text_checked`, after an `exists()` probe, and takes the mtime with a following `stat`. `wf_set_handoff_response` calls `server_impl._refuse_runtime_lock_target`, then `mkdir(parents=True)`, then `Path.write_text`. `server_impl.wf_pause_wave_response` and `wf_close_wave_response` also write the handoff the same way. Every one follows a link at the final component and at any directory component, with no regular-file check, size cap or containment check.
- Shared reader: `server_impl._read_repo_text_checked` is `_refuse_runtime_lock_target` followed by `Path.read_text`. `_refuse_runtime_lock_target` resolves the path, judges the resolved name and hard-link identity (`_is_runtime_lock_path`, through `lifecycle_gate_support.runtime_lock_identities`) and opens nothing, so the caller's later open is a second, unchecked step. Direct callers of `_read_repo_text_checked` (census by `rg`, 11 functions): `get_prompt` (nested `read`), `_read_doc_or_not_found`, `_validated_wave_markdown`, `resource_project_overview`, `resource_seed`, `resource_architecture`, `resource_codebase_map`, `resource_area_context`, `wf_get_handoff_response`, `wf_pause_wave_response`, `wf_close_wave_response`. `_read_doc_or_not_found` serves `resource_prompt_index`, `resource_architecture_current_state`, `resource_session_handoff` and `resource_agents`; `_validated_wave_markdown` serves `resource_current_wave` and `resource_wave`; `get_prompt` serves `resource_prompt`, `wf_get_prompt_response` and `McpRepoCache.get_prompt_text_cached`. `get_prompt`'s nested `read` catches only `RuntimeLockTargetRefused`, records the candidate in `refused` and continues with the next candidate. `tests/test_code_reader_lock_guard.py` `CheckedReaderCensusTests` pins the guarded function set.
- Member-doc reader: `_read_member_doc_bytes(folder, path, *, root)` raises `MemberDocRefused` (an `OSError`, `EPERM`, path-free cause text) and caps at `MEMBER_DOC_MAX_BYTES` (8 MiB). Every caller passes `path.parent` as `folder`, so root containment carries the rule. It refuses a final-component link (`lstat` must show a regular file). Its POSIX open is `O_NOFOLLOW` on the final component only; directory components are judged by `resolve()` before the open. On Windows (`O_NOFOLLOW` absent) it uses a plain open after the `lstat` and containment checks, with the window documented, and has no reparse-point check. `200v1`'s `wave_lint_lib/helpers.read_record_text` wraps it and maps causes by `strerror` text (`_refusal_cause`).
- Renderer reads and writes (`render_platform_surfaces`): `write_text(path, content, executable=False)` compares through a following `exists()`/`read_bytes()`, writes with `path.open("w")` (truncate in place, follows a final link), and for executable outputs calls `path.chmod(path.stat().st_mode | 0o111)` through the path, even when the content is unchanged. It has 13 call sites (`write_hook_bundle`, `render_claude_settings`, `render_claude_permissions`, `_merge_mcp_server`, `render_codex_mcp_config`, `render_cursor_hooks`, `render_copilot_hooks`, `render_bin_launchers` twice, `render_windsurf_hooks`, `render_aiignore`, `render_gitignore_block`, `render_gitattributes_block`); `write_hook_bundle` and `_merge_mcp_server` take no repository root today. The existing-config merge reads (`render_claude_settings`, `render_claude_permissions`, `_merge_mcp_server`, `render_codex_mcp_config`, `render_aiignore`, `render_gitignore_block`, `render_gitattributes_block`) read the current file by path with `read_text` or `open`. The `--manifest` write in `main` targets a caller-owned path: its only caller, `wf_server/docs_handlers`, passes a file in a `tempfile.TemporaryDirectory`, outside the repository.
- Renderer reads and writes (`render_agent_surfaces`): its own `write_text(path, content)` compares and truncates in place like the one above; the marker-block writers `patch_thin_pointer` and `patch_root_bridge` and the legacy-line strips for `CLAUDE.md` and the Cursor context file read with `read_text` and write with `Path.write_text` (default newline translation); template, seed and install-asset reads come from the framework directory or the packaged fallback beside the module.
- Install log: `install_log_lib.read_install_log` checks `exists()` and reads the whole file with `read_text(errors="replace")`. Callers: `setup_wavefoundry._install_in_progress` (treats `OSError` as "install in progress"), `wf_server/upgrade_handlers.wf_audit_install_response` (no `OSError` handling), and the install-audit advisory in `server_impl.wf_audit_response` (inside a broad `except Exception: pass`, so a failed read is silent).
- Prompt moves in `render_agent_surfaces`: `migrate_change_prompt_renames` preflights with `_change_prompt_pair_conflict` and then reads the resolved source with `read_bytes()`; `migrate_profile_prompt_names` (through `_move_prompt_pair`) reads the resolved source the same way; both publish `bytes` through `_write_review_carrier_text(..., exclusive=True)`, which delegates to `_write_bytes_atomic_exclusive`. `migrate_review_plan_prompt` reads the resolved source as text with `open` and publishes a `str` through `_write_review_carrier_text(..., exclusive=True)`, which takes the `O_EXCL` `os.open` branch, not the atomic writer. Every destination is created with mode `0o666` less the umask, so no move keeps the source's mode.
- Existing descriptor-anchored patterns to reuse rather than reinvent: `upgrade_extensions._journal_open_dir` and `_write_journal_exclusive` (POSIX `dir_fd` component walk, gated by `_journal_dir_fd_supported`; kept local there because the module runs pack-loaded), `runtime_lock._open_lock_carrier`, `upgrade_wavefoundry._remove_retired_component`. Windows link detection is split: `runtime_lock._is_windows_link` refuses only name-surrogate reparse points (symlinks and mount points, so OneDrive placeholders pass), and `upgrade_bridge_bootstrap._is_windows_link` is an existing copy of it; `render_agent_surfaces._is_link_or_reparse` and `bytecode_cache` refuse any reparse point.
- Out-of-scope readers with the same shape: `dashboard_lib.collect_activity` reads the handoff by path, and `docs_gardener.ensure_session_handoff` creates the handoff stub by path.

## Requirements

1. **One primitive.** A new leaf module `contained_files.py` in the framework scripts directory, importing only the standard library, owns the rule. It follows change `1zyv1`'s library-module bytecode guard, and it is listed in `mcp_tool_extensions.FRAMEWORK_SCRIPT_MODULE_NAMES` so no distribution module can shadow it. It provides `read_contained_bytes(root, path, *, max_bytes)`, `write_contained_bytes(root, path, data, *, mode=None, executable=False)`, `open_contained_dir(root, rel)`, `DEFAULT_MAX_BYTES` (8 MiB, equal to `MEMBER_DOC_MAX_BYTES`, pinned by a test), `ContainedFileRefused(OSError)` (`EPERM`, cause-class text only, never a path or file content) and `runtime_lock_identities(root)`, moved here from `lifecycle_gate_support`, which re-exports the same name. Its Windows name-surrogate predicate is a copy of `runtime_lock._is_windows_link` with a parity test over the same reparse tags (the precedent is `upgrade_bridge_bootstrap._is_windows_link`); its containment comparison is `Path.is_relative_to` on resolved paths, the comparison `path_containment.contained_resolved_path` makes.
2. **Directory walk helper.** `open_contained_dir(root, rel)` takes `rel` relative to the resolved root (callers pass a resolved relative path) and, where `dir_fd` is supported, returns a directory descriptor opened one component at a time from the resolved root with `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` (the `upgrade_extensions._journal_open_dir` pattern); a component that is a link at that moment raises `ContainedFileRefused`, and the caller closes the descriptor. Without `dir_fd` support (Windows) it returns `None` after checking that every existing component is a directory, is not a name-surrogate reparse point and resolves inside the root; the caller then acts by path, with the documented window. Both branches are tested in `tests/test_contained_files.py` (the Windows branch by simulation).
3. **Read rule.** `read_contained_bytes` reads `path` only when: its lexical form is under `root` (`..` refused); its fully resolved path lies inside the resolved root, so any link component, the final one included, whose resolution stays inside the repository is followed, and one that leaves it is refused; the resolved target is a regular file (`lstat` of the resolved path; on Windows also not a name-surrogate reparse point); it is not a hard link to a runtime lock (`runtime_lock_identities`, judged before any open); and at most `max_bytes` + 1 bytes are read, with more refused. On POSIX with `dir_fd` support, the resolved parent is opened with `open_contained_dir`, and the resolved final name is opened relative to it with `O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC`; the `fstat` of the open descriptor must be a regular file whose `(st_dev, st_ino)` equals the `lstat` identity. A component swapped for a link after the checks makes the open fail, and that failure is a refusal. A missing file raises `FileNotFoundError` as today; a link whose target is missing is a refusal.
4. **Write rule.** `write_contained_bytes` applies the same resolution, containment and walk to the resolved target, so a write through a link that stays inside the repository writes the link's target and leaves the link in place, and a link that leaves the repository is refused. It refuses when the existing resolved target is not a regular file, writes `data` to an exclusive no-follow temporary file in the resolved parent, sets its mode on the descriptor (`os.fchmod`: the existing target's permission bits when it exists, else `mode` or `0o666` less the umask, plus `0o111` when `executable`), flushes it, and publishes it with `os.replace` relative to the directory descriptor. Nothing is ever written or chmodded through a path that could be a link: an entry swapped for a link after the check is replaced as a directory entry, never followed. When the bytes are unchanged and the mode already matches, it writes nothing. On Windows, an `os.replace` that fails with a sharing violation (`PermissionError`) is retried a bounded few times over a short interval (at most about half a second in total), then refused with a path-free cause.
5. **Member-doc reader on the primitive.** `lifecycle_gate_support._read_member_doc_bytes` keeps its signature, its folder check, its own final-component link refusal (the wave `1zxo0` record-read rule is unchanged), `MEMBER_DOC_MAX_BYTES` and the `MemberDocRefused` class, and delegates the read to `read_contained_bytes`, re-raising its refusal as `MemberDocRefused` with the same cause text. The cause strings `200v1`'s `_refusal_cause` maps are pinned by a test so the two cannot drift.
6. **Handoff.** `wf_get_handoff_response` reads through the primitive (cap: `MEMBER_DOC_MAX_BYTES`) and takes the mtime from the descriptor's `fstat`, not a following `stat`. `wf_set_handoff_response`, `wf_pause_wave_response` and `wf_close_wave_response` write the handoff through `write_contained_bytes` and read any prior text through the primitive. The parent directory is created only when absent, with `mkdir` of the lexical path after confirming each existing ancestor resolves inside the repository. A content larger than the cap is refused before writing.
7. **Prompt and resource readers.** `_read_repo_text_checked` keeps its name and its existing runtime-lock refusal (so a lock target still yields `runtime_lock_target_refused` or the `# Refused` page, as `ResourceLockTargetTests`, `PromptLockTargetTests` and `HandoffLockTargetTests` pin), then reads through the primitive instead of `read_text`, decoding as today. A `ContainedFileRefused` is handled per caller: `get_prompt`'s nested `read` treats it like a lock refusal (the candidate's repository-relative path is recorded in `refused` and the search continues, so one refused prompt file does not hide another prompt); `_read_doc_or_not_found` and `_validated_wave_markdown` return their existing unreadable shape with a path-free cause; and the resources with no unreadable shape today (`resource_seed`, `resource_project_overview`, `resource_architecture`, `resource_codebase_map`, `resource_area_context`) return a path-free "unavailable" markdown page naming the cause class. The rule, not the list, governs: the implementer reruns the census (every server function that reads a repository file to serve a prompt, a resource or the handoff) and records it.
8. **Renderer reads and writes.** Every repository read and write in `render_platform_surfaces.py` and `render_agent_surfaces.py` goes through `contained_files`, rooted at the repository being rendered: both `write_text` functions, the existing-config merge reads listed above, the marker-block writers and legacy-line strips, and the non-exclusive branch of `_write_review_carrier_text`. `render_platform_surfaces.write_text` gains a `root` argument, passed at all 13 call sites (`write_hook_bundle` and `_merge_mcp_server` gain a root parameter from their callers); `executable` maps to the mode bits. Comparison and merge reads use `DEFAULT_MAX_BYTES` (8 MiB) as the cap. Reads of framework source (templates, seeds and install assets under the framework directory or the packaged fallback) go through the primitive rooted at the resolved framework directory the module locates, so a linked framework directory keeps rendering. The marker-block writers keep today's bytes on each platform (they encode after the same newline translation `Path.write_text` applies today). Not repository files and outside the rule: the `--manifest` write (a caller-owned temporary path) and the hook-source text that the renderer emits as a string. The exclusive branch of `_write_review_carrier_text` and `_write_bytes_atomic_exclusive` (Requirement 10) keep their own exclusive no-follow `os.open` relative to an `open_contained_dir` descriptor and are listed census exclusions. Removals (`unlink` and `rmdir`) are outside this requirement; the skill removals are change `200eu`'s. The census of both modules (each site, its route) is recorded in the Progress Log. Rendered bytes and modes for ordinary files are unchanged.
9. **Install log.** `install_log_lib.read_install_log` reads through `read_contained_bytes` with `DEFAULT_MAX_BYTES` as the cap and decodes as today (`errors="replace"`); a missing log still returns `None`. A refused or oversized log raises `ContainedFileRefused`. `wf_audit_install_response` maps it to an error response with `status: unreadable_log` and a path-free diagnostic; `wf_audit_response`'s install-audit advisory adds a path-free `install_log_unreadable` diagnostic instead of passing silently; `setup_wavefoundry._install_in_progress` keeps answering "install in progress" (it already catches `OSError`). No caller shows raw exception text or a path outside the repository.
10. **Prompt moves.** `migrate_change_prompt_renames`, `_move_prompt_pair` and `migrate_review_plan_prompt` read the source through `read_contained_bytes`, not the resolved path, and publish the destination with the source's permission bits (taken from the `lstat` identity the primitive matched). `_write_review_carrier_text` and `_write_bytes_atomic_exclusive` gain a `mode` parameter: the atomic writer applies it with `os.fchmod` on the temporary file before the exclusive publish, and the `str` branch applies it with `os.fchmod` on the `O_EXCL` descriptor before writing. Both exclusive writers keep their exclusive, no-follow semantics and, where `dir_fd` is supported, create relative to a descriptor from `open_contained_dir`. Conflict, resume and link-report behavior is unchanged.
11. **Docs and disclosure.** `docs/architecture/threat-model.md` states that repository reads and writes for the session handoff tools, the prompt reader, the read-only MCP resources, the two surface renderers, the install-log read and prompt moves go through one contained primitive, with the Windows residual window below, and names the dashboard activity handoff read and the gardener's handoff stub as not yet covered. `docs/architecture/cross-cutting-concerns.md` names `contained_files` as the owner of the rule. One CHANGELOG security bullet names exactly those covered classes and credits the Waveforge maintainers; its text is recorded in the Progress Log for change `200ew`, which writes the wave's `## [1.29.0]` bullets.

## Platform Behavior

- Linux, macOS and WSL2 (distribution filesystem): `dir_fd` is supported (`os.open in os.supports_dir_fd`), so reads and writes walk the resolved parent with `O_DIRECTORY|O_NOFOLLOW` and act relative to its descriptor; no check-to-use window remains for links. WSL2 on a mounted Windows drive (`/mnt/c`) behaves as Linux for the walk; links there are reported by the kernel as symlinks.
- Windows: there is no `O_NOFOLLOW` and no `dir_fd`. The fallback keeps the lexical containment, resolved containment, `lstat` regular-file and name-surrogate reparse-point checks (symlinks and junctions; OneDrive and deduplication placeholders pass, as in `runtime_lock`), opens by path, and compares the open handle's `fstat` `(st_dev, st_ino)` with the `lstat` identity; a mismatch is a refusal. Writes create the temporary file exclusively in the resolved parent and publish with `os.replace`, which replaces a link entry rather than writing through it; a sharing violation on replace is retried a bounded few times, then refused. The remaining window is a directory component swapped for a junction between the check and the open or replace; it is documented in the threat model, as for the member-doc reader. Mode handling is limited to what Windows supports (the executable bit does not exist; `fchmod`, where unavailable, is skipped and only the read-only attribute could differ).
- Links that stay inside the repository are followed on every platform (resolution then containment), so a symlinked prompt file or an in-repository linked directory keeps working; only the member-doc reader keeps refusing a final-component link, as it does today.
- FIFOs and other special files are refused before open by `lstat` on every platform; on POSIX the `O_NONBLOCK` open and `fstat` check also catch a swap.

## Risks

| Risk | Mitigation |
| ---- | ---------- |
| A repository relies on writing the handoff or a rendered surface through a link that leaves the repository. | The refusal is explicit and path-free; the CHANGELOG names the class. Links that stay inside the repository keep working. |
| Atomic replace changes inode and drops extra hard links on rendered files. | Rendered files are framework-owned outputs; hard-link sharing of them is not a supported layout. |
| On Windows, `os.replace` drops the replaced file's ACLs and extended attributes (accepted). | Rendered surfaces and the handoff are framework-owned files with inherited permissions; a custom ACL on them is not a supported layout. |
| Windows residual window. | Documented in the threat model; matches the existing member-doc and lock-carrier limits. |
| The copied Windows predicate drifts from `runtime_lock`. | A parity test over the same reparse tags. |
| Shared files with `200eu` (`render_agent_surfaces.py`). | Lands first; `200eu` rebases on it. |
