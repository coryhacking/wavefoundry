# Inert Upgrade Preview and Attestation Display

Change ID: `200ev-bug inert-upgrade-preview-and-attestation-display`
Change Status: `implemented`
Owner: framework-operator
Status: planned
Last verified: 2026-10-07
Wave: 200ey containment-and-distribution-seams

## Rationale

The Waveforge maintainers reported, and the operator verified, three gaps around the upgrade extensions and review display. A journal migration preview, documented as changing nothing, executes the distribution's declaration module to learn its templates, and several upgrade helpers add the target's framework scripts directory to the module search path and never remove it, so later imports in the same process can resolve against a tree they did not intend (low to medium). A self-attested approver name may contain parentheses and lookalike brackets, so the review status line "by NAME (handle)" can be made to show a handle that is not the operator's (low). And the journal pre-migration hook, with the journal migration behind it, runs only for upgrades from before 1.15.0, while its own skip warning tells the operator that "a later upgrade" will finish the work, which no later upgrade does (public report R8).

Brief: goal is a preview that executes nothing, scoped search-path changes, an unambiguous attribution display, and a journal hook skip warning that states the real recovery path; consumers are distribution maintainers (preview, hook), upgrade operators and reviewers reading the review status; success is that each gap has a failing-before, passing-after test and ordinary upgrades and approvals behave as today. Public repository: defect classes only.

Code-grounded facts (verified against HEAD `b97fa4ba` on 2026-10-07; wave `200xy` is committed as `2ebce84e` and `204jj` as `b97fa4ba`):

- Preview: `upgrade_extensions.migrate_journals(root, apply=False, templates=_UNSET)` loads its default templates with `_load_journal_declaration(root, load_hook=False)`, which executes `<root>/.wavefoundry/framework/scripts/mcp_tool_extensions.py` through `_exec_module_from_file` under a private module name and then calls that module's own `journal_declaration_problems`. The docstring says "with `apply` False nothing on disk changes"; executing the module can do anything the module does. The apply path, `pre_docs_gate`, calls `_load_journal_declaration(ctx.root)` itself and passes the templates to `_migrate_journals`, so it never uses the default. Wave `200xy` (change `200v2`) loads the incoming `history_paths` for `_preview_role_field_backfill` privately (`_incoming_history_paths`), without `sys.path`, which is the model here. `index_compatibility._read_literals` is the precedent for reading module-level literals with `ast` without executing the module.
- Search path: `upgrade_extensions` has nine `sys.path.insert` sites of the target's scripts directory (`<root>/.wavefoundry/framework/scripts`) with no matching removal (`_stop_dashboard_for_lock_cutover`, `_installed_memory_backfill`, `_installed_upgrade_module`, `_refresh_record_layout_modules_at_extraction`, `_migrate_memory_naming`, `_load_journal_hook`, `migrate_journals`, `repair_declaring_scaffold`, `_backfill_role_field_on_agent_docs`). Each insertion is guarded by "not already present", so it changes `sys.path` only when the process's own scripts directory is not the target's. `_load_journal_hook` inserts so that a hook module may import helpers declared before it, and the hook is called later by `_run_journal_pre_migration_hook`. `upgrade_wavefoundry.py` inserts its own `SCRIPTS_DIR` at module top and in two functions. The runner calls the incoming extension in-process: `_run_hook` for `pre_docs_gate` and `post_docs_gate`, and `phase_dry_run` for `post_extract`.
- Attestation: `review_evidence.normalize_attested_by` (write side, NFC then `attested_by_problem`) and `attested_by_problem` (also used by `_validate_operator_context` to validate stored names as stored, never re-normalized) forbid `<>`, backtick, `|`, `[`, `]`, backslash, three separators and categories `Cc`, `Cf`, `Cs`. Parentheses and other bracket characters are allowed. The review status builds `f" by {attested} ({handle})"` when both are present.
- Journal gate: `upgrade_extensions.pre_docs_gate` runs `_load_journal_declaration`, `_migrate_memory_naming`, `_run_journal_pre_migration_hook` and `_migrate_journals` only inside `if _from_version_predates(from_version, "1.15.0")`, which its comment calls "a cheap skip; the migration itself is idempotent". `_run_journal_pre_migration_hook`'s skip warning says "a later upgrade or the Migrate journals prompt finishes the work". `tests/test_upgrade_wavefoundry.py` `JournalDeclarationMigrationTests.test_hook_is_not_called_after_1_15_or_by_the_preview` pins today's gate.
- Tests: `AttestedByReviewEvidenceTests` is in `tests/test_review_evidence.py`; `AttestedByIntegrationTests` is in `tests/test_review_operator_integration.py`.

Public addendum (2026-10-07), A3, from the Waveforge maintainers; facts verified against the same tree:

- The reported import failure in the role-field preview is already fixed by wave `200xy` change `200v2`: `upgrade_extensions._preview_role_field_backfill` resolves `is_history_path` through `_incoming_history_paths(zip_path)`, which loads the incoming `history_paths` privately. Nothing more is planned for it here.
- Preview logs: a dry run (`upgrade_wavefoundry.phase_dry_run`) calls the incoming pack's `post_extract` with `dry_run=True`. Its preview branch writes `.wavefoundry/logs/upgrade-migration-1.5.0.preview.log` (`_write_migration_preview_report`, when any section has records) and `_run_convergence_migration` writes `.wavefoundry/logs/upgrade-convergence-migration.preview.log` (`_write_convergence_preview_report`, when legacy config keys are planned). Both create `.wavefoundry/logs/` if needed and write by path with `write_text`. The only operator-facing note is on stderr ("see <absolute path> for details (no files modified)").
- Final line: `phase_dry_run` ends with `_log("No changes were made. Run without --dry-run to execute the upgrade.")` and then `_emit_summary_line`, the machine-readable sentinel line (`WAVE_UPGRADE_SUMMARY_SENTINEL` plus JSON) that `wf_upgrade_response` parses. So the last human-readable line says no changes were made while the run wrote up to two files into the target. Earlier in the same function, the preview block checks `preview_log.is_file()` for the 1.5.0 log only and prints it as `preview log: <absolute path>`, so it also reports a preview log left by an earlier run as this run's, and never mentions the convergence preview log.

## Requirements

1. **Inert preview.** `migrate_journals(apply=False)` executes no repository code. When `templates` is not given, it reads the declaration statically: the module source is read through `contained_files.read_contained_bytes` (change `1zyv2`) with a cap, parsed with `ast`, and only the module-level assignment of `EXTENSION_JOURNAL_TEMPLATES` is evaluated with `ast.literal_eval` (the `index_compatibility._read_literals` pattern). The preview never calls the hook, so it reads neither `EXTENSION_JOURNAL_PRE_MIGRATION_HOOK` nor `EXTENSION_HELPER_MODULES`. The value is accepted when it is a tuple or list of non-empty strings that `_compile_journal_template` (the compile the apply path uses) accepts; validation of the declaration as a whole stays with the module's own `journal_declaration_problems`, which the apply path keeps calling unchanged (one owner; no reimplementation in `upgrade_extensions`). Any parse, evaluation or acceptance failure, including `SyntaxError`, `ValueError`, `RecursionError` and `MemoryError`, as well as an unavailable `contained_files` or a refused read, adds one path-free "not statically readable" warning to the report, and journals that only a declared template would delete are listed under `left`. `contained_files` is loaded privately, the way `_incoming_history_paths` loads `history_paths` (beside this module, or the member of the incoming pack), never through `sys.path`. `apply=True` keeps today's executed loading.
2. **Scoped search path.** Every `sys.path` insertion in `upgrade_extensions` is undone when the function that made it returns (in `finally`, only when that call inserted it); `_load_journal_hook`'s insertion is held across the hook's load and its call in `_run_journal_pre_migration_hook`, then removed. `upgrade_wavefoundry`'s insertions of its own `SCRIPTS_DIR` (module top and two functions) are unchanged: they add the runner's own directory, not the target's, and are not the defect class. Modules imported while an insertion was in place stay cached in `sys.modules`; that caching is out of scope. The implementer reruns the census (`rg "sys.path.insert"` over `upgrade_extensions.py`) and records it.
3. **Unambiguous attribution, on display only.** The review status display renders every attested name with each character of Unicode category `Ps` or `Pe` (every opening and closing bracket, including fullwidth, small, superscript and ornamental parentheses) replaced by U+FFFD at render time, so a name can never show a bracketed handle. Nothing changes at write time: `normalize_attested_by` and `attested_by_problem` are unchanged, no new name is refused, no stored approval becomes invalid, no ledger is rewritten and replay is unchanged.
4. **Truthful skip warning; the 1.15.0 limit stays and is documented.** The `pre_docs_gate` version gate is unchanged: the declaration load, the pre-migration hook and the journal migration run only on an upgrade from a release before 1.15.0. `_run_journal_pre_migration_hook`'s skip warning stops promising that a later upgrade finishes the work: it says the journals were left in place, that later upgrades do not retry the migration or call the hook again, and that the Migrate journals prompt finishes the work, still naming only the hook and the exception class. `docs/specs/mcp-tool-surface.md` (**Declared journal migration**) and seed `210-migrate-journals.prompt.md` state that the hook is called only on an upgrade from before 1.15.0, is never retried, and is never called by the Migrate journals prompt.
5. **Proposed CHANGELOG bullet.** Recorded in the Progress Log for change `200ew`, which writes the wave's `## [1.29.0]` bullets.
6. **Dry run names its preview logs.** The dry run keeps writing its preview logs. `phase_dry_run` records, before it calls the incoming `post_extract`, the identity (`lstat` presence, `st_mtime_ns`, `st_size`) of each `*.preview.log` under `.wavefoundry/logs/`, and after the call treats a log as written by this run when it is new or its identity changed. The final human-readable line (the one before the summary sentinel) names each such log by repository-relative POSIX path, for example "No upgrade changes were made; wrote preview log(s) .wavefoundry/logs/upgrade-migration-1.5.0.preview.log, .wavefoundry/logs/upgrade-convergence-migration.preview.log. Run without --dry-run to execute the upgrade.", and keeps today's wording when the run wrote none. The preview block's `preview log:` listing uses the same written-this-run set and prints each path repository-relative, so a log from an earlier run is not presented as this run's and no absolute path is printed. The summary sentinel gains the additive `preview_logs` field of Requirement 8.
7. **Truthful, contained preview writes.** The incoming extension's migration preview (`upgrade_extensions` `post_extract`, the `dry_run` branch that prints "upgrade-migration preview: N planned action(s); see PATH for details (no files modified)" to stderr, currently at the `report_path = _write_migration_preview_report(...)` block) stops claiming that no files were modified, because it has just written a preview log. The wording states which preview log was written, as a repository-relative POSIX path, for example "upgrade-migration preview: N planned action(s); wrote preview log .wavefoundry/logs/upgrade-migration-1.5.0.preview.log (no other files modified)", and when `_write_migration_preview_report` returns no path it says that no preview log was written. The convergence preview message (`_run_convergence_migration`, "upgrade-convergence preview: ... see PATH") gets the same repository-relative path rendering instead of an absolute one. `_write_migration_preview_report` and `_write_convergence_preview_report` write through `contained_files.write_contained_bytes` (privately loaded as in Requirement 1); when it cannot be loaded or refuses, the report is not written and the message says no preview log was written. The writer creates `.wavefoundry/logs/` only when absent, the 1zyv2 Requirement 6 way (a lexical `mkdir` after confirming each existing ancestor resolves inside the repository). This is effective for incoming packs at 1.29.0 and later; older packs keep their old wording and writes, and the dry run's final line (Requirement 6) is the surface that is correct for every incoming pack.
8. **`preview_logs` in the dry-run sentinel.** `phase_dry_run` sets `dry_summary["preview_logs"]` before `_emit_summary_line`: the list of repository-relative POSIX paths of the preview logs written this run (the Requirement 6 written-this-run set, sorted), and an empty list when none. The field is additive: `SUMMARY_SCHEMA_VERSION` stays 1 and `_RECOGNIZED_SUMMARY_SCHEMAS` is unchanged, because the producer-side parser (`_delegated_summary_payload` check on `summary_schema_version`) and the server's `_bounded_upgrade_summary` (`wf_server/upgrade_handlers.py`) read named keys and pass unknown ones through (a list is capped as a collection), so an older consumer ignores the field and a newer consumer reading an older producer's sentinel treats an absent field as unknown, not as empty. The field is set in `phase_dry_run` after `_build_upgrade_summary`, not inside the shared builder, so the primary-phase and cleanup summaries keep their shared key set (the superset test around `test_upgrade_wavefoundry.py` line 7575 stays green). `_emit_summary_line` itself is unchanged.

## Scope

**Problem statement:** the journal preview executes repository code, upgrade extension helpers leave the target's scripts directory on the search path, a self-attested name can imitate a handle in the status display, and the journal hook's skip warning promises a later upgrade that never retries it.

**In scope:**

- Requirements 1 to 5 in `upgrade_extensions.py`, `review_evidence.py` and their tests.
- Requirement 6 and Requirement 8 in `upgrade_wavefoundry.phase_dry_run` and its tests (`tests/test_upgrade_wavefoundry.py` `DryRunTests`; the sentinel is parsed in `tests/test_server_tools.py` around the summary-schema tests, which gain a `preview_logs` case).
- Requirement 7 in `upgrade_extensions.py` (the migration and convergence preview messages and report writers) and its tests.

**Out of scope:**

- `upgrade_wavefoundry`'s insertions of its own scripts directory.
- `sys.modules` caching of modules imported while an insertion was in place.
- Write-time refusal of bracket characters in attested names, and confusable names outside the bracket categories (the name is self-attested by definition and the handle is shown in its canonical form).
- Other preview sections and the server's own extension loader.
- Re-validating stored names.
- The role-field preview import failure (A3), fixed by `200v2`.

## Platform Behavior

- The static reader, the search-path scoping and the attestation display are pure Python with identical behavior on Windows, macOS, Linux and WSL2. The declaration source is read, and the preview reports are written, through `1zyv2`'s primitive, so its platform behavior (descriptor-anchored on POSIX, checked open and replace with a documented window on Windows) applies.
- The dry-run log paths are rendered relative to the repository root with `/` separators on every platform (Windows included), and the identity probe is an `lstat` with nanosecond mtime and size, so a rewrite within one timestamp tick that keeps the size is the documented miss (the log carries a run timestamp line, so its size rarely stays equal).

## Risks

| Risk | Mitigation |
| ---- | ---------- |
| A distribution builds its templates with code, not literals. | The preview warns and lists those journals as left; the real upgrade still executes and applies them. |
| The preview accepts a literal template that the module's `journal_declaration_problems` rejects at apply time. | The apply refuses the whole declaration and leaves the journals, as today; the preview over-reports deletions only for an invalid declaration, which the real upgrade reports. |
| A hook relied on the target's scripts directory staying on `sys.path` after the upgrade. | The path is held across the hook's load and call; nothing after the hook depends on it. |
| A distribution with leftover journals after a failed hook has no automatic retry. | The warning, the spec and seed 210 name the Migrate journals prompt as the path. |
