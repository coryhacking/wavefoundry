## Rationale

The Waveforge maintainers' private report, verified by the operator, names four low-severity classes in `render_agent_surfaces`: declared-skill orphan removal decides on one check and removes by path later, so the entry removed may not be the entry judged; several render error messages carry absolute paths or raw exception text; a deeply nested prompt-surface manifest stops the render with an uncaught error instead of the manifest's unreadable outcome; and the moved-prompt link report prints repository file names to the terminal without neutralizing control characters. Wave `200xy` (change `200v2`) made only the orphan unlink failure message path-free. Each remaining item is a place where repository content or local paths reach an operator's terminal or logs, or where a check and its action are separated.

Brief: goal is that render removals act on the entry they judged, and render messages carry only repository-relative paths, exception class names and neutralized names; consumers are operators and distribution maintainers running renders and upgrades; success is identical renders for ordinary repositories and no absolute path, raw exception text or raw control character in any render message. Public repository: defect classes only.

Code-grounded facts (verified against HEAD `b97fa4ba` on 2026-10-07; wave `200xy` is committed as `2ebce84e` and `204jj` as `b97fa4ba`):

- Orphans: `_declared_skill_orphans(active_skill_roots)` judges each candidate folder and its `SKILL.md` by `os.lstat` plus `_is_link_or_reparse` (directory, regular file, declared marker, exactly one entry) and returns `(rel, skill_file, child)` path tuples with no file identity. `render_skills` later calls `skill_file.unlink()` and `folder.rmdir()` by lexical path with no re-check. A failed unlink raises `RuntimeError(f"cannot remove the undeclared skill {rel} ({type(exc).__name__})")` (path-free since `200v2`); a failed rmdir is a NOTICE. Between its `lstat` checks and the marker test, `_declared_skill_orphans` reads `SKILL.md` with a following `read_bytes()`.
- Stale skill paths: `render_skills` checks each stale path's parent containment by `resolve()`, then runs `stale.is_file()` (which follows a final link), `stale.unlink()` and `parent.rmdir()` by lexical path, with no recorded identity.
- Messages: `_resolve_install_asset` raises `missing install scaffold baseline` naming two absolute paths (the target path and `Path(__file__).resolve()`'s packaged fallback). `_declared_prompt_doc_creations` re-wraps that error with `{exc}`. In `render_skills`, `declared host skill root cannot be resolved safely` and `stale skill path cannot be resolved safely` interpolate `{exc}`. `_declared_skill_orphans` raises `cannot list the host skill root` with `{exc}`. `_contained_review_carrier_path` raises `review carrier path cannot be resolved safely` with `{exc}`, which `_change_prompt_pair_conflict` passes on. `_write_review_carrier_text` and `_write_bytes_atomic_exclusive` raise `review carrier write refused for {path}: {exc}` at every failure site, where `path` is the resolved absolute path and `{exc}` the `OSError` text. The verification counted four raw messages in `render_skills`; this re-check found two there plus the sites above, so the requirement states the rule rather than a count.
- Manifest: `_repair_change_prompt_manifest` and `_read_prompt_manifest` both read the manifest and call `json.loads`, catching `(OSError, UnicodeDecodeError, ValueError)`. `RecursionError` is not a `ValueError`, so a deeply nested manifest escapes both (`inferred` from the code; AC-3 executes it). `render_platform_surfaces.load_payload_strict` already catches `(ValueError, RecursionError)`.
- Link report: `_moved_prompt_link_report` returns `f"{rel}:{line_no}"` entries for repository files, printed raw to stderr by two NOTICE lines in `render_agent_surfaces` (`change_migration.link_report` and `profile_migration.link_report`). No shared terminal-display helper exists; `vendored_integrity._unsafe_char` (C0, DEL, C1, category `Cf`) is the closest precedent.

## Requirements

1. **Orphan removal acts on the judged entry.** `_declared_skill_orphans` records the `lstat` identity (`st_dev`, `st_ino`) of each orphan folder and `SKILL.md`, and reads `SKILL.md` for the marker test through `contained_files.read_contained_bytes` (change `1zyv2`'s Requirement 8 census covers this read). On POSIX with `dir_fd` support, `render_skills` opens the host skill root and the orphan folder with `contained_files.open_contained_dir(root, rel)` (change `1zyv2`'s walk helper), checks the folder descriptor's and the `SKILL.md` entry's identities (`os.stat(..., dir_fd=..., follow_symlinks=False)`) against the recorded ones, then removes `SKILL.md` with `os.unlink(..., dir_fd=folder_fd)` and the folder with `os.rmdir(..., dir_fd=root_fd)`. A mismatch skips that orphan with a NOTICE naming its repository-relative path and the cause class. On Windows the same identity re-check runs by path immediately before each removal, and the remaining window is documented. Stale skill paths get the same treatment: the stale file is judged by `lstat` (a regular file, not a link or reparse point) with its identity recorded, then removed relative to a descriptor from `open_contained_dir` after the identity re-check, and its emptied per-skill folder is removed relative to the host skill root's descriptor; a link or a mismatch is skipped with the same NOTICE. Existing failure semantics (unlink failure raises and stops before skill writes; rmdir failure is a NOTICE) are unchanged.
2. **Message rule.** Every `RuntimeError`, `ValueError` and NOTICE raised or printed by `render_agent_surfaces` names repository-relative paths (or a fixed label such as "the packaged fallback") and exception class names only, never an absolute path and never `str()` of an `OSError` or a wrapped exception. The governing set is derived by that rule: the implementer censuses every f-string in `render_agent_surfaces.py` that interpolates an exception value or a path that can be absolute, routes each hit, and records the census. Every raised or printed message that interpolates a repository file name renders it through the Requirement 4 display helper. Named sites from planning: `_resolve_install_asset`, the `_declared_prompt_doc_creations` wrap, the two `render_skills` resolution messages, the `_declared_skill_orphans` listing message, `_contained_review_carrier_path`, and every `review carrier write refused` site.
3. **Manifest readers.** `_repair_change_prompt_manifest` treats a `RecursionError` from parsing as an unreadable manifest (returns its existing empty result), and `_read_prompt_manifest` raises its existing `ValueError` with a class-only reason. Neither lets `RecursionError` escape.
4. **Neutralized display names.** A single helper in `render_agent_surfaces` renders a repository-relative path for terminal output with every character of Unicode category `Cc`, `Cf`, `Cs`, `Zl` or `Zp` replaced by its `\uXXXX` escape. Both link-report NOTICE lines and every other NOTICE, `RuntimeError` or `ValueError` message in the module that interpolates a repository file name use it. The returned `link_report` tuple keeps raw names (callers and tests compare them); only display is neutralized.
5. **Proposed CHANGELOG bullet.** Recorded in the Progress Log for change `200ew`, which writes the wave's `## [1.29.0]` bullets.

## Scope

**Problem statement:** render removals act on a path judged earlier, and render messages can carry absolute paths, raw exception text or raw control characters; a deeply nested manifest stops the render.

**In scope:**

- Requirements 1 to 5 in `render_agent_surfaces.py` and its tests.

**Out of scope:**

- Messages in other modules (the upgrade preview's tracebacks remain out of scope as in `200v2`).
- Changing what the link report detects, or rewriting links.
- Manifest size caps (not reported).

## Platform Behavior

- Linux, macOS and WSL2: orphan and stale-path removal is descriptor-relative (`dir_fd` with `follow_symlinks=False`). The window narrows to an entry swapped inside the verified, descriptor-held directory between the identity re-check and the removal; such a swap is removed as a directory entry and never followed, and removal never leaves that directory.
- Windows: no `dir_fd`; the identity re-check runs by path immediately before each unlink and rmdir, and a junction or link swapped in between is the documented remaining window. `_is_link_or_reparse` keeps judging reparse points as today.
- Messages, manifest parsing and the display helper are string operations with identical behavior on every platform; repository-relative paths are printed in POSIX form everywhere.
