## Rationale

Framework-managed regions in markdown are fenced by HTML comment markers of the form `<!-- <namespace>:<name> begin -->` and `<!-- <namespace>:<name> end -->`. The canonical namespace is `wave` (seed 100, item "Install-time lifecycle propagation and marker namespace"), and two legacy namespaces, `waveframework` and `wavefoundry`, are still accepted. The fork audit (`docs/reports/waveforge-fork-audit.md`, "Good news: the carve out cleanly infrastructure") noted that the chunker's region regex anticipates several product-name prefixes but not `waveforge`, and assigned the one-line addition to whoever performs the merge. The operator chose to do it now.

The census for this plan found the alternation is not one line, and found a latent defect beside it. Three sites carry their own alternation literal for markers that a project author might write: `chunker._WAVEFRAMEWORK_MARKER_BEGIN_RE` (three namespaces), `server_impl._WAVE_MARKER_BEGIN_RE` and `_WAVE_MARKER_END_RE` (three namespaces, named-or-bare end; consumed by `codenav_handlers` for the `code_read` marker-region listing), and the lookahead inside `render_agent_surfaces.strip_legacy_auto_guru_section` (two namespaces, so it never stops at a `wavefoundry:` marker; no test calls that function). The chunker's end regex, `_WAVEFRAMEWORK_MARKER_END_RE`, matches only the bare `<!-- end -->` form. Every framework renderer writes named ends, so inside `_strip_waveframework_marker_regions` a named end never closes a region and everything after the first begin marker is swallowed; the zero-content guard then emits zero chunks for a file whose leading content is a named region followed by hand-authored prose. Two reviewers reproduced it: such a file gives zero chunks today and two chunks with a named-or-bare end. A census of this repository's working tree (tracked plus untracked) found 161 markdown files with begin markers and zero whose chunk count changes under the corrected end pattern, so the Wavefoundry index is unaffected; consumer repositories are unmeasured.

Other modules hold whole-string marker literals for names the framework itself writes: `review_evidence`, `context_efficiency`, `gen_codebase_map`, `review_policy`, `review_policy_reconcile`, `memory_supply`, and the `_LEGACY_OWNED_MARKERS` table in `render_agent_surfaces` (`exploration_avoided` carries canonical `wave:` names only). None contains a namespace alternation; a fork's namespace never appears in what the framework writes, so they are out of scope.

Adding `waveforge` in three places by hand would be the fourth divergent literal. The change instead follows the pattern the operator chose for record roots in wave `1y0gz`: one module-level constant, edited at merge time, with every author-facing site derived from it.

## Requirements

1. A new module `.wavefoundry/framework/scripts/marker_namespaces.py` SHALL export `MARKER_NAMESPACES: tuple[str, ...] = ("wave", "waveframework", "wavefoundry", "waveforge")`; a builder `compile_marker_patterns(namespaces) -> (begin_re, end_re, alternation)` where `alternation` is the source fragment `(?:wave|waveframework|wavefoundry|waveforge)`, `begin_re` captures the marker name as group 1 and ends at `begin\b` like the current server regex (not the chunker's stricter `begin\s*-->`), so annotated begin markers such as `<!-- wave:auto-guru begin — generated by ... -->`, which the renderers write, stay recognized by `code_read`; and `end_re` accepts both the named and the bare `end` forms with the optional name as group 1 exactly as the current server regex does; and module-level defaults `MARKER_NAMESPACE_ALTERNATION`, `MARKER_BEGIN_RE` and `MARKER_END_RE` built by that builder. The module imports nothing from the framework. Its docstring names the merge-time edit.
2. The three author-facing sites SHALL derive from the module and carry no private alternation literal, looking the patterns up at call time as module attributes so a test can rebuild and patch them: `chunker` uses `MARKER_BEGIN_RE` and `MARKER_END_RE` (its bare-only end regex is retired); `codenav_handlers` reads `marker_namespaces` directly instead of the two `server_impl` regexes, which are removed; and the stripper constructs its pattern on each call from `marker_namespaces.MARKER_NAMESPACE_ALTERNATION`, without a cached consumer pattern, keeping its exact `\n<!-- ` anchoring so whitespace tolerance does not change. The import in `server_impl.py` and `chunker.py` is a plain module-body `import marker_namespaces`, not the `__import__` call style used beside the old regexes, so the import-derived purge census sees it.
3. Three behavior changes on existing input are intended and SHALL be pinned by tests: the stripper's boundary gains `wavefoundry` and `waveforge`; a named `end` now closes a chunker region, so a document whose leading content is a named region followed by hand-authored prose chunks that prose instead of emitting zero chunks; and the chunker's zero-content guard now recognizes annotated begin markers, so a document consisting only of annotated regions emits zero chunks. Chunk output also changes for a document consisting only of `waveforge:` regions (chunks today, zero after). Working-tree census: 1,906 markdown files, 29 with annotated-only begins, zero whose zero-content status flips under the loose begin form. No other behavior on existing input changes.
4. `CHUNKER_VERSION` SHALL NOT be bumped in this wave. Operator decision: Waveforge is substantially behind upstream and its version number will be updated as part of the downstream merge. That merge must verify that the adopted version invalidates the old index and re-chunks affected documents. This is a downstream integration obligation, not evidence supplied by this wave. Other consumer repositories may retain old chunk output until affected files are edited or a full rebuild runs; the local census does not establish their safety. The CHANGELOG bullet SHALL state this limitation and the rebuild remedy without asserting a numeric version bump, and contain no `to <number>` or `at <number>` phrase within eighty characters after the backticked constant name, which the changelog claims lint would read as a numeric claim.
5. `marker_namespaces` SHALL be added to `index_compatibility._SOURCE_NAMES` because it affects chunk output. The existing runtime source capture and stale-runtime guard SHALL cover replacement of this module. A focused test SHALL capture the source, replace the namespace module bytes, and verify that the real guard reports `index_runtime_stale` for `marker_namespaces`; an unchanged source must pass. Use the child-process temp-copy shape of `test_loaded_model_and_lazy_producer_refuse_same_stat_source_replacement` in `test_index_compatibility.py`, asserting both the error code and the `component` name, since the capture is process-immutable. `marker_namespaces` does not call `register_loaded_source()` (that would import the framework), so its coverage is the byte hash in `ensure_runtime_current` reached through the producers' registration and connection checks; that is sufficient and is stated here so a reviewer does not flag the absent call. The only guard-owned obligation on `index_compatibility.py` is to leave the top-level `INDEX_GUARD_CAPABILITY` assignment intact; editing `_SOURCE_NAMES` does not touch it. Keep the module free of framework imports and preserve the existing restart-to-adopt contract.
6. Because `server_impl.py` gains a new sibling import, the module SHALL be added to the reload purge list; `test_reload_purge_covers_direct_sibling_imports` enforces this. The pack ships the module automatically because packaging walks the scripts directory.
7. Tests SHALL: pin the constant's four names; before rewiring, add a baseline test for `strip_legacy_auto_guru_section` (none exists) that pins today's two-namespace boundary in both directions, then after rewiring assert the boundary stops at each of the four namespaces; exercise a `waveforge:x` region through the real `chunker.chunk_file` (zero chunks for an all-region document), through the real `code_read` response (marker region listed with its name and lines), and through the stripper; pin the marker-first named-end case in the chunker (prose after a named region now chunks); include an in-test self-mutant that rebuilds the patterns without `waveforge` through the builder, patches the module attributes, and asserts the three site tests fail; and add a source census asserting that no regex alternation whose alternatives include two or more distinct names from `MARKER_NAMESPACES` exists under `.wavefoundry/framework/scripts/` outside the new module, with no allowlist; the census walks that directory excluding `tests/`, `__pycache__` and `.pytest_cache` as `test_record_layout_census.py` does, and tests derive any expected alternation from `MARKER_NAMESPACES` or the builder rather than spelling one; plus a polarity self-mutant that plants one such literal in a temp tree and asserts the census reports it. Existing tests `test_marker_region_only_markdown_file_emits_zero_chunks`, `test_marker_region_only_code_file_emits_zero_chunks`, `test_marker_regions_accept_legacy_namespace` and `test_marker_regions_detected_when_in_range` pass unmodified.

## Scope

**Problem statement:** the author-facing marker namespace alternation is duplicated in three divergent literals, the chunker's end form is inconsistent with the server's and swallows named regions, and a fork needs a fourth namespace.

**In scope:**

- The new constant module with its builder and defaults.
- Rewiring the three author-facing sites, including retiring the chunker's bare-only end regex and the two `server_impl` regexes.
- The reload purge list entry and runtime source-compatibility coverage in `index_compatibility.py`.
- Tests, both self-mutants, the stripper baseline and the literal census.
- A CHANGELOG Unreleased bullet, worded without a numeric `CHUNKER_VERSION` claim.

**Out of scope:**

- The framework-owned marker modules and their canonicalization paths.
- Any rename of what the framework writes (`wave:` stays canonical; `wavefoundry:review-policy` stays as written by `review_policy`).
- A `CHUNKER_VERSION` bump in this wave; the operator assigns the bump and invalidation verification to the downstream merge (Requirement 4).
- Configuration for the namespace list; it is a module constant by the same reasoning as `record_paths`.
