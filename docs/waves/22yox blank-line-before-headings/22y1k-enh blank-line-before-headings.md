Wave: 22yox blank-line-before-headings

## Rationale

A Markdown heading written straight after a non-blank line is a common defect in this repository's records. In this plan a heading is an ATX heading: up to three leading spaces, one to six `#` characters, then a space, a tab or the end of the line (so `#tag` and `#######` are not headings). A line is blank when it is empty or holds only spaces and tabs. Observed on 2026-11-10, by a census of the Markdown files under `docs/`, the root and `.wavefoundry/framework/` with fenced lines skipped: 583 headings follow a non-blank line (two independent counts agree on 583; their totals of headings scanned differ, 27,335 and 30,006, because of how each counted `#` lines). The line before the heading is a list item in 412 cases, an HTML comment in 123 and prose in 48. 35 of the 583 follow the opening marker of a renderer-owned block and are not defects (see below).

The producers:

1. **Wave summary at close.** `_generate_wf_close_wave_summary` in `.wavefoundry/framework/scripts/wf_server/server_impl.py` returns the summary without a trailing newline, and `_replace_wave_summary_section` appends one `\n` before the next `## ` heading, so the last bullet runs into `## Watchpoints` (waves 22vgm and 23041). The same summary has two content defects seen in 23041:
   1. It quotes up to three Progress Log entries across all changes, chosen by keyword ("removed", "added", "scope" and others). Most entries are review-round notes, so it repeated a 150-word cap that a later round removed, and any keyword rule still picks bookkeeping notes.
   2. It counts only `[x]` criteria and omits `[~]` ones, so 23040's summary read "2 ACs completed" with no mention of its deferred AC-3. This breaks the close contract in `docs/prompts/close-wave.prompt.md` ("the close summary in `## Wave Summary` must list every `[~]` AC across the wave's admitted changes, grouped by change, with the inline status note").
2. **Exploration-avoided projection.** `replace_checkpoint_block` in `.wavefoundry/framework/scripts/exploration_avoided.py` (not the same-named function in `context_efficiency.py`) appends the text after `<!-- wave:exploration-avoided end -->` with `.lstrip("\n")`, removing the blank line, so the marker runs into the next heading, usually `## Review Checkpoints`. 88 cases.
3. **Memory records.** 38 records in `docs/agents/memory/` have a heading straight after a metadata line (`Canonical overlap:`, `Archive path:`, `Updated:`): 23 active and 15 archived. The current writers do not cause this. `render_memory_record` writes a blank line before `## Summary`; `_replace_or_insert_metadata`, used by validation and archiving, keeps exactly one since commit `fd73691d` (2026-09-22); `reconcile_memory_record` inserts only before the `Kind:` line. No test pins their spacing.
4. **Hand-authored documents.** Outside closed waves and archived memories, 24 headings in 24 files are defects: the 23 active memory records and `docs/references/enterprise-delivery-model.md` line 2. None is rendered from a seed or template.

The 35 exempt cases follow a renderer's opening marker. Every such marker in the repository has a colon-separated name and one of two forms: `<!-- <name>:begin -->` (for example `<!-- wavefoundry:review-policy:begin -->`) or `<!-- <namespace>:<name> begin ... -->` (for example `<!-- wave:executable-review-evidence begin — generated by ... -->`). The heading is part of that block's generated content, and inserting a line would make the block differ from its renderer's output.

## Product Intent

Readers and tools get Markdown in which every heading has a blank line above it, so it renders as a heading and parsers agree on section boundaries. Prepare fixes a wave's own documents, the producers stop writing the defect, and docs-lint warns about it in live documents without failing any repository, including downstream ones, on upgrade. The close-time wave summary reports each change's completed and deferred criteria accurately. Closed wave records and archived memories are not rewritten.

## Requirements

1. A function `ensure_blank_line_before_headings(text) -> str` in a new module `.wavefoundry/framework/scripts/markdown_layout.py`, which imports only the standard library and `change_doc_checklist`, inserts one empty line before each heading whose previous line is not blank, except:
   1. a heading on the first line of the document;
   2. a heading inside a closed fenced block, per `change_doc_checklist.fenced_line_flags`;
   3. a heading whose previous line, stripped of leading spaces, opens a renderer block: it matches `<!--\s*[A-Za-z0-9_.-]+(?::begin\b|(?::[A-Za-z0-9_.-]+)+(?::begin\b|\s+begin\b))`, which accepts `<!-- x:begin -->` and `<!-- x:y begin -->` but not `<!-- x begin -->` or `<!-- we begin here -->`;
   4. a heading inside a blockquote, which it leaves unchanged.

   It keeps the document's line endings (`\r\n` or `\n`) and changes nothing else, and applying it twice gives the same text as applying it once.
2. `wf_prepare_wave` in modes `ready` and `create` applies the function to the wave record and each admitted change document inside its `if _mutating:` preflight block, after `run_garden` and before the docs lint and the post-garden re-read, so the review-policy receipt is computed from the fixed text. Writes go through `contained_files.write_contained_bytes`. `dry_run` and `evaluate` write nothing.
3. `wf_close_wave(mode="create")` applies the function to the wave record text after inserting the wave summary and before writing `wave.md`. A retry on an already closed wave does not apply it. No other document is touched at close.
4. `_replace_wave_summary_section` leaves one empty line between the summary and the next heading. `_generate_wf_close_wave_summary` stops quoting Progress Log entries, and drops the "Notable adjustments" sentence. Each change's bullet then states its outcome from its acceptance criteria:
   1. the completed criteria by label (for example "AC-1 and AC-2 completed");
   2. each `[~]` criterion by label with its full inline status note: the `*Status: ...*` continuation line if present, otherwise the italic segment on its first line;
   3. a bullet is written for every change, including one whose criteria are all deferred.

   The existing "Key decisions" from the Decision Log stay.
5. `replace_checkpoint_block` in `exploration_avoided.py` keeps one empty line between `<!-- wave:exploration-avoided end -->` and the following text.
6. A docs-lint check, registered in `SENSOR_POLARITY_REGISTRY` as `heading_without_blank_line_before` with polarity `advisory`, introduced and decided in wave `22yox`, reports each heading the function would change. It covers every Markdown file under `docs/` and the repository root. It never reports a file in a wave folder whose `wave.md` is closed (per `wave_validators.status_drift_exempt`), anything under the record archive root (`helpers.is_under_archive_root`) or under `memory_records.MEMORY_ARCHIVE_DIR`. It reports a blockquoted heading too, since the function does not fix those. As a warning it fails no lint run, prepare, close or upgrade.
7. The 24 headings in 24 live files listed in Rationale item 4 get the mechanical fix; closed wave records and archived memories are not edited.
8. Tests pin the memory writers' spacing: one record rendered with `render_memory_record`, then validated, archived and reconciled, has an empty line before `## Summary` after each step.
9. `docs/specs/mcp-tool-surface.md` gains one sentence in the `wf_prepare_wave` entry, and `docs/architecture/data-and-control-flow.md` one sentence in item 8 (prepare) and one in item 9 (close), saying prepare and close insert a missing blank line before headings in the wave's own documents. `docs/prompts/close-wave.prompt.md` is unchanged; the summary now meets its `[~]` contract.
10. The CHANGELOG `[Unreleased]` section gains one bullet ending "Wave 22yox / change 22y1k."

## Scope

**Problem statement:** two producers and some hand edits write headings straight after text, and the close-time summary omits deferred criteria and quotes arbitrary review notes.

**In scope:**

- `markdown_layout.py` (new) and its calls in `wf_prepare_wave` and `wf_close_wave`; `_generate_wf_close_wave_summary` and `_replace_wave_summary_section` in `server_impl.py`; `replace_checkpoint_block` in `exploration_avoided.py`; the advisory check in `wave_lint_lib/wave_validators.py` and its registry entry in `wave_lint_lib/constants.py`.
- Memory-writer spacing tests; a writer change only if a test fails.
- The 24-file fix-up (Requirement 7), the spec and architecture sentences (Requirement 9) and one CHANGELOG bullet.
- Tests in `test_markdown_layout.py` (new), `test_server_tools_lifecycle.py`, `test_context_efficiency.py`, `test_memory_records.py` and `test_docs_lint.py`.

**Out of scope:**

- Closed wave records, their change docs and archived memories.
- Renderer-owned blocks: the 35 headings after a `begin` marker stay as they are.
- Setext headings, spacing after a heading, and a heading at the end of a file with no newline after it.
- Making the check an error; a later wave can decide that once live documents are clean.

**Platform behavior:** text handling only. The function keeps each document's line endings, so a CRLF document stays CRLF. The same on Windows, macOS, Linux and WSL2.
