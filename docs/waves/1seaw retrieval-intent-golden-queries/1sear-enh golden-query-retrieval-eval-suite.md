## Rationale

External code review (2026-07-12) + this repo's own history converge on the same gap: ranking/classification changes here ship eval-gated (the AC-8 gate that killed `code_risk_score` v1; the AC-10 recall comparison for agent-mode `code_ask`), but every gate so far has been BESPOKE — assembled per change, then discarded. There is no standing, repeatable retrieval evaluation, so (a) each ranking change re-pays the harness cost, (b) regressions between changes are invisible, and (c) observed quality issues (the review session's "where are the gaps?" queries ranking `.aiignore` comments above implementation; the session-8 "what value is X" constant-ranking weakness; the multi-token summary-first behavior) are recorded as memory anecdotes instead of failing test cases.

This change builds the suite; `1seas` (classifier/ranking improvements) is gated on it. It also seeds the review's proposed scheduled evaluation without committing to CI infrastructure yet.

Voyage Code 4's published evaluation supplies one useful benchmark shape without changing Wavefoundry's local-only model policy: ask with a natural-language issue description, then score whether retrieval finds the files that contain the fix. Wavefoundry will adopt that evaluation pattern using locally curated change records and Git provenance. It will not adopt a hosted embedding dependency or make `voyage-4-nano` a delivery assumption; the current shared embedder is the approximately 33.2M-parameter `Snowflake/snowflake-arctic-embed-s`, while the 0.3B class (`voyage-4-nano` is approximately 340M total parameters) has not met the operator's practical local runtime envelope.

## Requirements

1. **Golden-query corpus, versioned in-repo:** known-answer queries against THIS repo's indexed content, each with expected top-hit path(s)/symbol(s) and question-type expectations. Seed classes (from live evidence): architecture/review intent ("where are the biggest gaps in X"), known-symbol navigational, constant-value lookup, exact-identifier lexical, error-string lookup, enumeration ("which X are…"), direct ignore-file/manifest questions (the ONLY class where low-information paths are the right answer), abstention cases (absent topics must return low confidence, not fabrication), and **agentic fix localization** (a symptom/problem statement must retrieve the implementation and supporting paths that contain its fix).
2. **Metrics:** Recall@k and nDCG@k against expected hits; MRR@10 / first-relevant rank for agentic fix-localization cases; abstention correctness on the negative controls; p95 latency and response size per tool (`code_ask`, `code_search`, `docs_search`, `code_lexical`). Agentic cases use graded relevance (primary implementation paths above supporting tests/specs) and report nDCG@10. Cached-model runs only (no network).
3. **Frozen evaluation environment (plan-review addition; reconciled with wave `1sed7`):** before/after comparisons run against a generation-frozen index state — the runner snapshots the index-state store's BUILD GENERATION across the run (post-`1sed7`, the store's generation row is the canonical index signature; `meta.json` is retired), constructs `WaveIndex` without `ImplHandler`'s background monitors, and invalidates the report if any external hook, host, or process changes the generation. The runner does not claim authority to disable external refresh producers. The report records model names/versions, execution provider, and hardware; p95 latency is computed from repeated samples after a documented warm-up (never from a cold first call).
4. **Calibration/holdout split (plan-review addition):** the corpus separates CALIBRATION cases (visible during `1seas` tuning — includes the verbatim misranked queries) from WITHHELD validation cases (paraphrases/novel instances of each class, not consulted during tuning); the gate verdict weighs the holdout set, so the classifier cannot be tuned to the exact queries that declare success.
5. **Local agentic fixture provenance:** add at least ten fix-localization cases sourced only from committed Wavefoundry bug/enhancement change docs and local Git history, split at least five calibration / five holdout. Each fixture records the natural-language query, source change/commit provenance, graded expected paths, and a short relevance rationale. At least half are symptom-only queries with filenames and implementation symbols removed. Human verification distinguishes primary implementation from supporting test/spec paths and excludes incidental generated, manifest, or mechanical files unless they are the subject of the change. The suite evaluates the CURRENT built index; it must not represent this small curated corpus as a historical pre-fix-snapshot benchmark.
6. **Runnable locally in one command:** `python3 -B .wavefoundry/framework/scripts/retrieval_eval.py --root . --fixtures docs/evals/retrieval-quality-golden.json --out docs/reports/retrieval-quality-baseline.json` is the canonical baseline invocation; comparison runs add `--baseline <report.json>`. The versioned report schema is `wavefoundry.retrieval-eval/v1` and contains the input generation(s), fixture digest/count, model/provider/hardware environment, per-tool/class/split metrics, per-case normalized ranks/anchors, cold and warm latency, serialized-envelope bytes, threshold calculations, invalidation reasons, and verdict. JSON is emitted with UTF-8, sorted keys, and stable indentation; response byte measurement uses compact UTF-8 JSON with sorted keys. Verdicts are `baseline`, `pass`, `fail`, `operator_review_required`, or `invalid`; exit 0 is `baseline`/`pass`, exit 1 is `fail`/`operator_review_required`, and exit 2 is invalid arguments, missing cache/index/corpus, generation drift, timeout, or other invalid execution.
7. **Baseline recorded:** the current scores land in the change doc / a report artifact as the reference line `1seas` must beat-or-hold.
8. **Gate wiring:** documented (contributing/review docs) as the required evidence for future ranking/classification/chunking-relevance changes — the standing replacement for bespoke gates.
9. **Production-path fidelity (2026-08-30 audit addition):** the standing suite SHALL load the current Lance/FTS index state and invoke the same public retrieval response paths used by `code_ask`, `code_search`, `docs_search`, and `code_lexical`. The retired `docs.json`/`code.json` representation and raw dense-cosine ranking SHALL NOT stand in for production hybrid fusion, query-prefix handling, reranking, filters, partitioning, confidence, or degraded modes. The existing dense-only benchmark may remain only as an explicitly named component benchmark and must fail honestly when its expected corpus is absent.
10. **Per-tool applicability and relevance:** every fixture SHALL declare `applicable_tools` and a reason for every excluded tool/query pair. Relevance SHALL be graded at the public tool's output unit: path-only labels are permitted only when the file is itself the target; shared or monolithic files require a symbol, line-span, section, or distinctive-content anchor so an unrelated chunk from the right path cannot pass. Exact-token `code_lexical` SHALL be scored only on query classes compatible with its public contract.
11. **Frozen execution seam:** the runner SHALL avoid starting the background staleness monitor, capture the published build generation before and after each run, and invalidate a run if that generation changes. A controlled before/after comparison MAY span two explicitly recorded generations when the evaluated change rebuilds the index, but each constituent run must remain generation-frozen. Degraded-mode cases SHALL use a bounded injected or temporary-store seam and SHALL NOT corrupt or mutate the published project index.
12. **Bounded performance gate:** after one untimed warm-up per tool, every applicable tool/query pair SHALL run three measured repetitions; the warm-up elapsed time (including cold model construction) is recorded separately and excluded from warm p95, and p95 uses nearest-rank over the pooled warm samples. The runner SHALL cap the corpus at 48 fixtures, query text at 512 UTF-8 characters, repetitions at three, and total wall time at 20 minutes. Per-call timeouts are fixed at 30 seconds for `code_ask`, 15 seconds for `code_search`/`docs_search`, and 5 seconds for `code_lexical`; the 20-minute total timeout overrides any remaining call budget, and either timeout is a failed run rather than a missing sample. For each tool, same-generation latency jitter is the absolute difference between the two baseline-run warm p95 values divided by the lower non-zero p95; the permitted relative regression is exactly `max(25%, 3 * jitter_ratio)` against the second frozen baseline run. The serialized full response envelope SHALL not regress beyond the larger of 15% or 4 KiB. A result also requires explicit operator review rather than PASS when warm p95 exceeds 5 seconds for `code_ask`, 3 seconds for `code_search`/`docs_search`, or 1 second for `code_lexical`, or when any serialized response exceeds 256 KiB. Cached/offline model readiness is proven before timing begins.

## Scope

**Problem statement:** ranking changes need an eval gate, and each one has been built from scratch and thrown away; known quality anecdotes aren't executable.

**In scope:** eval harness over the current public production retrieval paths + nine-class golden corpus + locally curated, provenance-backed agentic fix-localization fixtures + metrics + baseline + gate documentation; explicit repair, retirement, or component-benchmark naming for the obsolete JSON-loading dense benchmark.
**Out of scope:** any ranking change itself (that is `1seas`); embedding-model replacement or training; hosted inference/API use; assuming a roughly 0.3B-parameter local model is viable; automatic mining and indexing of historical pre-fix repository snapshots; CI scheduling (operator infra decision — the suite must merely be CI-invocable later); consumer-repo query packs (the multi-language test-pack `p4ea` can extend this later).

## Risks


| Risk | Mitigation |
| ---- | ---------- |
| Index drift makes runs incomparable | Each constituent run is valid only when internally generation-frozen; a controlled pre/post rebuild comparison may span two explicitly recorded generations, and the tolerance check quantifies within-generation noise. |
| Corpus overfits to this repo | Acceptable for the gate's purpose (this repo IS the dogfood); consumer packs (p4ea) extend later. |
| Treating every file touched by a historical fix as equally relevant rewards generated or mechanical noise | Human-review every agentic fixture, use graded primary/supporting relevance, record rationale, and exclude incidental paths. |
| Issue text leaks filenames or implementation symbols and makes localization trivial | Mark query form explicitly; require at least half of agentic cases to be symptom-only and keep at least five agentic cases withheld. |
| The standing suite grows into an unbounded or performance-blind gate | Freeze its sample protocol and corpus/query/runtime ceilings; compare warm p95 and serialized envelope bytes to the frozen baseline, and require operator review at absolute ceilings. |
| Wave close relocates a labelled report and the evaluator refuses the corpus | The assessment fixtures label `docs/reports/index-quality-audit-dispositions.md` (and the audit prompt beside it); those files stay in `docs/reports/` at close (they are not wave-owned records), or the evaluator raises `stale_corpus` on the next run and the labels must be re-pointed (cycle-2 reverification, ARCH-RV-1). |
