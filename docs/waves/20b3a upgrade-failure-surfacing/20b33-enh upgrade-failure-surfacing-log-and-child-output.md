# Upgrade Failure Surfacing: Early Log, Output Tail, and Index Child Output

Change ID: `20b33-enh upgrade-failure-surfacing-log-and-child-output`
Change Status: `implemented`
Owner: Engineering
Status: implemented
Last verified: 2026-10-10
Wave: 20b3a upgrade-failure-surfacing

## Rationale

A field upgrade (1.15.4 to 1.28.0, native Windows) failed three times with `Upgrade phase 'preflight_to_docs_gate' failed: docs gate failed` and the operator could not see the real error. Verification against HEAD confirmed three independent causes:

1. **The MCP response drops the tail.** `wf_server/upgrade_handlers.py:1269-1285` builds `output = stdout + stderr` and `wf_server/server_impl.py:3646-3660` (`_bounded_subprocess_output`) keeps the first 60,000 characters (`UPGRADE_OUTPUT_CAP_CHARS`, `upgrade_handlers.py:18`). `ERROR:` lines from `_err` sit at the tail and are lost. A structured `summary` survives only if the child printed its `WAVE_UPGRADE_SUMMARY_JSON:` sentinel, so a child that dies early leaves the reason only in the discarded tail.
2. **`upgrade.log` is opened too late.** `_open_log(root, mode="w")` is called at `upgrade_wavefoundry.py:6332`, after lifecycle lock acquisition (6233-6238), `phase_preflight` (6240), pack staging (6253-6260), the `post_preflight` extension hook (6268-6270), the review-policy preflight (6278-6282) and the MANIFEST snapshot (6287-6293). Failures at those points reach only stdout/stderr. The MCP handler pre-touches an empty file (`upgrade_handlers.py:1221-1229`), so `log_path` resolves to an empty or stale file. (The docs gate itself is NOT early; the log is already open there. The field report's suspicion about the docs gate was refuted.)
3. **Child failures carry no reason.** `phase_index_update` (`upgrade_wavefoundry.py:2783-2788`) calls `subprocess_util.isolated_run([...setup_index.py...], check=False)` with no `stdout`/`stderr`/`capture_output` argument and reports only `Semantic index update exited N` (line 2790). Today the child INHERITS the parent's streams, so on a CLI run the operator's terminal shows its output and under MCP `_mcp_subprocess_run` (`server_impl.py:639`) captures it into `output`. The missing failure reason in the message and the log is certain. That the child's stderr is actually lost under `pythonw.exe` on Windows (`_preferred_python()` at `upgrade_wavefoundry.py:191-203` prefers it; no console, `sys.stderr` is None; `isolated_run` at `subprocess_util.py:74-105` sets only `stdin=DEVNULL` and `CREATE_NO_WINDOW`) is **inferred, not demonstrated**, and the claim is scoped to `pythonw` on Windows. The prewarm call (`:2749`) uses the same pattern. A fuller spawn census, including `phase_index_rebuild`, the graph spawn and the docs-gate children, is in the Spawn Census section below.

Brief: goal is that any upgrade failure leaves its real reason in (a) the MCP response and (b) `upgrade.log` / a child log, on every platform. Audience: operators and agents diagnosing a failed upgrade. Constraints: no behavior change on the success path (the single permitted child environment addition is `PYTHONUNBUFFERED=1`, see Requirement 3), no new network use, the old-code window below. Exclusions: the 1.15.4 wrapper's exit-code-1-means-docs-gate mapping (shipped, cannot be fixed from this repo). Success: a forced failure at preflight, docs gate and index update each yields the reason in the MCP `data` and in a log file.

## Requirements

1. The upgrade log is opened for a FRESH full run immediately AFTER the lifecycle lock is acquired (after `upgrade_transaction.__enter__()` succeeds near `upgrade_wavefoundry.py:6233-6238`) and BEFORE `phase_preflight`, so every `_log`/`_err` line from preflight onward reaches `.wavefoundry/logs/upgrade.log`.
   - **Move, do not duplicate.** The late `_open_log(root, mode="w")` near `:6332` is REMOVED, and the `Upgrade log:` and `Watch:` lines near `:6333-6335` move to the new open point. If both opens stayed, the second `mode="w"` would truncate the preflight lines this change exists to capture.
   - **Lock-busy run.** A run the lock refuses (the `return 3` path near `:6238`) never reaches the open, so it neither opens, truncates nor writes the file, and the live run's log is byte-identical. (The pre-lock `_log` header near `:6226` stays stdout-only by decision; it runs before any log exists and a refused run must not write.) The only permitted alternative is to open in append mode with a run-separator line before the lock and truncate or rotate only after the lock is held; either way a lock-busy run leaves the first run's log byte-identical.
   - **Close on every post-open exit.** Once the log is open, `_close_log()` runs on every early return or raise after the open point (the `BaseException` handler around `phase_preflight` near `:6246`, the stage-pack failure near `:6258-6260`, the review-policy failure near `:6280-6282`, the MANIFEST snapshot failure near `:6291-6293`, and every later return), preferably through one `try/finally` around the post-open region, so the module-global log handle never leaks into embedded or test callers.
   - The `--resume-*` entry points already open the log in append mode (`_open_log(root, "a")` near `:5646`, `:5869`, `:5913`, `:5937`, `:6049`); their behavior is unchanged except that they open it through the same contained helper (Requirement 4).
2. The bounded MCP output keeps the head and the tail of the child output (with an explicit elision marker between them), and `data` additionally carries `error_tail`: the last `ERROR:`/failure lines extracted from the full untruncated output, bounded to 4,000 characters.
   - `output_truncated` and `output_total_chars` stay, with their current meanings.
   - The change is made through an upgrade-only wrapper, or an opt-in tail parameter on `_bounded_subprocess_output` whose default preserves current behavior, because the shared helper has other callers (`wf_server/docs_handlers.py:48` and `:121`) and a pin in `tests/test_handler_modules.py:153`. The upgrade handler passes its own cap (`UPGRADE_OUTPUT_CAP_CHARS`), not the shared default.
   - `error_tail` extraction, the `WAVE_UPGRADE_SUMMARY_JSON:` sentinel parse (`upgrade_handlers.py` near `:1301-1303`) and the existing `_index_pub_failed`, `_deps_failed` and `_retired_cleanup_failed` checks all run on the FULL untruncated output BEFORE bounding, never on the displayed head+tail text.
   - The response envelope `_bounded_upgrade_response_envelope` (`upgrade_handlers.py` near `:676-760`, `UPGRADE_RESPONSE_CAP_CHARS` 100,000) re-truncates when the total exceeds the cap and today keeps the head and drops the tail. It must be made tail-preserving for `output` (cut from the middle, keep the head, the elision marker and the tail, and never touch `error_tail`). The permitted alternative is to cap the head+tail budget to a named constant at or below `UPGRADE_RESPONSE_CAP_CHARS` minus a stated reserve for `error_tail`, `summary` and diagnostics. The implementer picks one and records it in the Progress Log.
3. Every in-scope spawn site in the Spawn Census captures the child's output with a TEE: the child's output is written to a per-run child log file AND still reaches the parent's terminal and the MCP `output` as it does today. Capture must not turn a streaming child into a silent one.
   - **Mechanism (decided).** Use `subprocess_util.isolated_popen` (exists at `subprocess_util.py:107`) with a drained reader thread (or one thread per stream) that writes each line to the per-run contained child file and to a None-safe pass-through to `sys.stdout`/`sys.stderr` (under `pythonw` those are `None`, so the pass-through must guard for that). `isolated_run` is a blocking `subprocess.run` and cannot tee. `isolated_popen` has different defaults from `isolated_run` (`start_new_session=True` on POSIX, and the detached-background creationflags `DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP|CREATE_NO_WINDOW` on Windows unless the caller passes `creationflags`), which would detach the foreground upgrade children from terminal Ctrl-C and from the console; the tee therefore passes `start_new_session=False` and `creationflags=no_window_creationflags()` so it matches `isolated_run`. The helper preserves the `isolated_run` isolation defaults (`stdin` DEVNULL, `CREATE_NO_WINDOW`, UTF-8 with replacement), `cwd`, `env`, timeouts and return code, and returns a `CompletedProcess`-compatible result so callers keep their `returncode` handling.
   - **One environment addition.** A piped Python child block-buffers its output, so a live tee needs `PYTHONUNBUFFERED=1` in the child environment. That is the single permitted addition to the child's environment and is excluded from the "environment unchanged" invariant in Requirement 6; no other variable is added or removed.
   - **Failure surfacing.** On a non-zero exit, the last N lines (bounded, each line capped in length) are appended to the failure message and to the upgrade log, before any `sys.exit`. With separate reader threads the relative order of stdout and stderr lines in a tail is best-effort, so each tail line is labelled by its stream.
   - `phase_docs_gate` passes `env={**os.environ, "PROJECT_ROOT": ...}` and then `sys.exit(1)`; the tee must preserve that `env` and `cwd` and append the tail before the exit.
4. A NEW contained create-or-append file open is added to `contained_files.py` (for example `open_contained_append(root, path, *, mode=0o600, truncate=False)`), because `contained_files` today exposes only `ensure_contained_dir`, `write_contained_bytes` (an atomic temp-file replace that cannot back a streaming handle), the read helpers, `judge_contained_file` and `unlink_contained`.
   - POSIX: `ensure_contained_dir` for the parent, then open relative to the directory fd with `O_WRONLY|O_CREAT|O_NOFOLLOW|O_CLOEXEC`, an `fstat` regular-file check, and `fchmod` to 0600.
   - Windows: run `_is_windows_link` (`contained_files.py:106`) before and after the open and fail closed. This is a by-path check with a residual TOCTOU window, which is documented in `contained_files.py` and stated here; it refuses symlinks and mount-point junctions (name-surrogate reparse tags) and deliberately tolerates OneDrive and dedup reparse points. Mode 0600 is POSIX-only; on NTFS the ACL inherits from the parent directory.
   - The early `upgrade.log` open (the plain `Path.open` in `_open_log`, `upgrade_wavefoundry.py:280-294`) is REPLACED by this helper (`truncate=True` for the fresh full run, append for the `--resume-*` opens), and the handler pre-touch (`upgrade_handlers.py:1221-1229`, a plain `mkdir` plus `touch`) is removed or converted to the same helper, since the early open makes it unnecessary.
   - Child logs are per-run files under `.wavefoundry/logs/` created through this helper. File names are generated by the upgrade code (phase label plus run id), never derived from child output or environment. Child-log opens use `truncate=False` plus a bounded suffix retry on a name collision and never truncate an existing file. Retention keeps the 5 most recent runs' child logs; pruning deletes only generated-name files, through `judge_contained_file` and `unlink_contained` (never following links), and never the current run's files.
5. Captured output is untrusted data. The current `WAVEFOUNDRY_UPGRADE_PUBLISHER_TOKEN` value (present in the index child's environment, `upgrade_extensions.py:2767-2782`) is scrubbed ON THE TEE PATH, before a line is written to the child file and before it is forwarded to the terminal or the MCP `output`, so the child log, the retained tails, `upgrade.log`, `error_tail` and the MCP `output` are all scrubbed. Redaction runs on ASSEMBLED lines (the reader assembles complete lines from the stream chunks, with a bounded line buffer that is flushed at the cap) and on the full line BEFORE the per-line length cap, so a token cannot survive by being split at the cap boundary or across two reads. C0 and C1 control characters other than `\n` and `\t` (ANSI escapes, a bare `\r` that overwrites a line, NUL) are stripped from tails, `error_tail` and logged lines. Tails are bounded to N lines with a per-line length cap, and `error_tail` to 4,000 characters.
6. Capturing child output must not change the child's argv, working directory, exit code or environment (apart from the single `PYTHONUNBUFFERED=1` addition in Requirement 3), and must not block on a full pipe (the reader thread drains continuously).
7. Existing success-path output, `WAVE_UPGRADE_SUMMARY_JSON:` sentinel handling and exit codes are unchanged.
8. MCP response compatibility. `error_tail` is an ADDITIVE key in `data`: it is absent (not null) on success. `output` changes from head-only to head plus elision marker plus tail, and `output_truncated` and `output_total_chars` keep their meanings, so a client that assumed `output` is a prefix of the child output must be told (Scope, the `docs/specs/mcp-tool-surface.md` task and the CHANGELOG bullet).
9. New helper modules are registered where the framework lists its modules. The tee helper lives in a NEW stdlib-only module (for example `child_tee.py`) beside `subprocess_util.py`, and `open_contained_append` lives in the existing `contained_files.py`. The implementer adds the new module to the extension module roster (`mcp_tool_extensions.py` near `:225-240`, which lists `setup_reconciliation`, `subprocess_util`, `upgrade_lib` and similar; `contained_files` is already listed, only the tee module is new, and it is placed alphabetically among its neighbours), imports the tee module LAZILY inside the phase functions that use it (never at `upgrade_wavefoundry` module import time) so a partially extracted tree in the mixed-version window cannot fail at import, adds it to `setup_readiness.py` `SOURCE_FILES` (near `:41-48`) only if a setup-path module imports it, and confirms the upgrade pack and MANIFEST include it, stating the readiness source-digest effect.

## Scope

**Problem statement:** An upgrade failure on Windows (and early failures everywhere) hides its real cause behind a truncated response, an unopened log and uncaptured child output.

**In scope:**

- Early log open in the FRESH full-upgrade entry point of `upgrade_wavefoundry.py` (the `--resume-*` entry points already append and keep that mode, now through the contained helper).
- Head+tail bounding, a tail-preserving response envelope and `error_tail` in the MCP upgrade handler through an upgrade-only wrapper or an opt-in parameter (default behavior preserved for `docs_handlers.py`).
- Tee capture, redaction, control-character stripping and tail surfacing for the in-scope sites in the Spawn Census, through a new stdlib tee helper module.
- A new contained create-or-append open in `contained_files.py`, and contained, 0600, per-run, bounded-retention log files.
- Tests for each, the `docs/specs/mcp-tool-surface.md` update (additive `error_tail`, `output` is head+marker+tail), and a CHANGELOG Unreleased bullet.

**Out of scope:**

- Changing the 1.15.4 installed wrapper's exit-code mapping.
- The CLI resume command text and gap-clear guidance (change `20b34-enh upgrade-cli-resume-and-gap-clear-guidance`).
- Moving or restructuring `upgrade.log` beyond when it opens.
- Fixing the underlying index failure seen in the field (separate causes).
- A child-written result-file design (rejected, see the Decision Log).

**Platform behavior (required statement):**

- Windows (native): the motivating case; child capture tees to a per-run file so it works whether the child is `python.exe` or `pythonw.exe`. The `pythonw` stderr-loss premise is inferred; the fix does not depend on it being true because the capture works either way. Per-run file names mean no overwrite of a previous log is needed; if a generated name is nevertheless locked (`PermissionError`), fall back to a further generated suffix, bounded in count, never a name derived from child content. Symlinks and junctions are refused through the by-path check with a documented residual TOCTOU window. The locked-file fallback and the Windows containment paths are verified by simulation (patched errors and a patched platform predicate) and are **inferred, not run on a real Windows host**.
- macOS, Linux, WSL2: same code path; files are created 0600 through the no-follow open relative to a directory fd. No windowless-interpreter special case; `PYTHONUNBUFFERED=1` applies to the child on every platform.

**Old-code window:** `upgrade_wavefoundry.py` and the MCP handler run as the INSTALLED version when an older install upgrades. This change improves a new-version runner and handler only; upgrades FROM versions without it still use the old behavior. The first upgrade carrying this change is therefore not self-protecting, and tests must not assume the old runner benefits. In particular, during that first upgrade the MCP handler is still the OLD handler, which truncates head-only at 60,000 characters and returns no `error_tail`, so the new runner's `upgrade.log` and per-run child logs are the durable recovery surface there. Documentation and the CHANGELOG bullet must not claim `error_tail` or head+tail MCP output for that first upgrade.

## Decision Log

| Date | Decision | Reason | Alternatives |
| ---- | -------- | ------ | ------------ |
| 2026-10-10 | Divergent pre-plan: selected approach C below. | Fixes all three causes at their source with the smallest surface. | A: only raise the 60,000 cap (rejected: still loses the tail on large plans and does nothing for the log or child output). B: only ask operators to run from a shell with redirected stderr (rejected: pushes the workaround onto every operator, already what the field did). C: early log + head/tail with `error_tail` + child output to file (selected). |
| 2026-10-10 | Child output is teed to a per-run contained file through `isolated_popen` and a drained reader, not redirected, with `PYTHONUNBUFFERED=1` as the only child environment addition. | Redirecting would silently remove live index output from the terminal and the MCP `output` on the success path; a tee keeps it and still records the reason. A piped Python child block-buffers, so without the variable the tee would show nothing live. A per-run generated name also removes truncation and most Windows lock cases. | Plain file redirect (rejected: changes the success path). In-memory pipe capture (rejected: deadlock risk without a drained reader). Reusing one overwritten file per child (rejected: lock fallback and concurrency problems). Child writes its own failure reason to a result file and the parent reads it on a non-zero exit (rejected: no tee and no buffering change, but it gives no live output, depends on every child cooperating, and loses the output of children the upgrade does not control). |
| 2026-10-10 | Open the fresh-run log after the lifecycle lock is held, and remove the late open. | Opening in mode `w` before the lock lets a refused concurrent run truncate the live run's log (red-team and security readiness finding); keeping the late open would truncate the lines the early open just wrote. | Open before the lock in `w` (rejected). Open before the lock in append mode with a run separator (permitted fallback, same byte-identical-on-refusal outcome). |
| 2026-10-10 | Add a new contained create-or-append open to `contained_files.py`. | `contained_files` has no streaming or append open (only atomic `write_contained_bytes`), so the plan's "no-follow open helpers" did not exist; without it the implementer would invent one unreviewed or fall back to a plain `open()`. | Plain `Path.open` (rejected: the planted-symlink truncate/append surface). Atomic `write_contained_bytes` of the tail only (rejected: cannot back a live tee). |
| 2026-10-10 | Redact on the tee path, before the file write and the forward. | Scrubbing only tails would leave the full child log and the live stream carrying the publisher token. | Scrub tails only (rejected). |
| 2026-10-10 | Upgrade-only bounding wrapper or opt-in tail parameter. | `_bounded_subprocess_output` has docs-handler callers and a pin; a head+tail default would change docs-lint and gardener responses. | Change the shared default (rejected). |

## Risks

| Risk | Mitigation |
| ---- | ---------- |
| Opening the log changes concurrent-run behavior | Open only after the lock is held; lock-busy run leaves the first log byte-identical (AC-2). |
| Leaving the late `mode="w"` open truncates the early lines | The late open is removed; AC-1 checks the preflight lines survive. |
| Log handle leaks on an early exit | One `try/finally` or `_close_log()` on each exit; AC-2 checks per exit. |
| Shared `_bounded_subprocess_output` has other callers whose behavior would change | Upgrade-only wrapper or opt-in parameter; AC-10. |
| Envelope re-cuts the tail the change keeps | Tail-preserving envelope or a capped head+tail budget; AC-3 near-cap test. |
| Windows locked log file | Generated, bounded suffix fallback (AC-6); verified by simulation only, not run on Windows. |
| Old-code window: first upgrade carrying this still uses the old runner and old MCP handler | Documented; no test assumes otherwise, including a mixed runner/handler pair; the CHANGELOG and docs do not claim `error_tail` for the first upgrade (AC-11). |
| Captured child output leaks the publisher token or injects terminal control sequences into a durable log or MCP client | Token scrub on the tee path before the cap, control-character stripping, bounded untrusted tails (AC-9). |
| New log files widen a planted-symlink surface | New contained create-or-append open, no-follow, 0600; Windows by-path check with a documented residual TOCTOU window (AC-8). |
| Tee changes success-path output, deadlocks, or shows nothing live because the child block-buffers | Drained reader thread, `PYTHONUNBUFFERED=1`, None-safe pass-through; AC-7. |
| Spawn census incomplete | Re-enumerate against HEAD; AC-5 records missed or out-of-scope sites. |
| New module is not in the roster or pack | Registration requirement and AC-12. |
| Overlap on `upgrade_wavefoundry.py` with `20b34` | `20b34` lands after `20b33`; the early-log-open hunk and the `command_argv` hunks stay separate (see wave Watchpoints). |
