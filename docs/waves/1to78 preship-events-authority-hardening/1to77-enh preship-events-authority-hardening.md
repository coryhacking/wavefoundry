## Rationale

Wave `1tomw` made each wave's `events.jsonl` the sole machine authority for review evidence and shipped clean, but the operator's post-close review identified six release-relevant defects that share one theme: the single-authority contract is not yet finished honestly. Review and close still derive operator/council signoffs and max-severity from `wave.md` prose, which is exactly the second-derivation shape the cutover removed elsewhere. The upgrade sidecar cleanup probes and releases the publication locks before deleting, leaving a demonstrated race window. The upgrade surface simultaneously mandates a full host restart for the 1.15 cutover and suggests or performs an in-process MCP reload, and it reports `restart_required` unconditionally forever. Retired inline-ledger compatibility code survives despite the clean-cutover contract. The residue census excludes tests, and the named crash cuts inject caught exceptions rather than terminating a process. Finally, the cheapest tamper path against a declared wave, deleting its one declaration line while its ledger survives, is documented as undetected but is statelessly detectable. One bounded correction wave fixes all six before the 1.15.0 release; none warrants its own wave, and together they close the contract.

## Requirements

1. **Typed-exclusive signoff derivation for declared waves.** On a wave carrying `review-evidence-source: events.jsonl`, every gate read of review-evidence content (operator-signoff presence, per-lane and council signoff currency, max-severity) must derive exclusively from typed `events.jsonl` records and their chronology. The readiness census found six prose-derivation surfaces, and all six are in scope: (a) the close gate (`server_impl.py:14325` operator presence, `:14363` per-lane scan, `:14383-14388` council); (b) the review implementation phase (`:13617-13663`, including `_max_severity_from_evidence` at `:13663`); (c) the review prepare phase (`:13591-13614`, lane signoffs read from `## Prepare Review Evidence` prose); (d) `wf_implement_wave` Gate 2 (`:13911-13927`, which re-reads the same prepare prose before opening a wave); (e) the transition-policy branch (`:2504-2521`), where prose signoff presence selects which council signoffs are required at close; on declared waves that presence probe must read typed approvals; (f) the `wf_prepare_wave` readiness council-signoff gate (`:13265-13283`, checking prepare-council signoffs against `## Review Evidence` prose via `_lane_has_signoff_in_evidence` at `:13270`). The facade takes the wave identity (root plus wave path), not bare text; carriers that today receive only text, such as `_required_wave_council_signoffs`, gain that identity through a named signature extension (every caller has the wave path in scope) rather than an improvised seam. The contract distinguishes prose-as-evidence (retired on declared waves at all five surfaces) from prose-as-configuration (the required-lane roster from `## Participants` parsing plus workflow-config: retained byte-for-byte; this wave makes no lane-parsing change, so waves whose Participants sections parse to empty rosters keep passing exactly as today). Implementation strategy is a single authority-resolution seam, not five point patches: one facade (working name `resolve_review_authority`, housed in `review_evidence.py`) exposes exactly the evidence reads the gates need and dispatches internally on the declaration, with the prose implementation demoted to the legacy branch inside it; all five surfaces consume the facade, and the residue census adds the prose-evidence tokens outside the facade (`_lane_has_signoff` variants, prose severity-word scans) to its forbidden list so any missed or future direct prose read fails the census instead of shipping silently. Legacy waves without the declaration keep the existing prose mechanism unchanged, as it is their only one. This retires the prose severity-word false-trip class for declared waves. Close-gate behavior on every existing declared wave in this repository must remain green, with the honest caveat that most declared waves parse to empty lane rosters, so the tree sweep proves topology preservation and legacy parity, not lane derivation; the AC-1 fixtures carry that proof.
2. **Cleanup holds its locks through deletion.** `phase_review_evidence_sidecar_cleanup` must hold the current publication lock and the v1.13 root lock for the duration of sidecar deletion instead of probe-then-release-then-unlink. The v1.13 root-lock file itself is released and then unlinked last (Windows cannot delete an open locked file); state that residual sliver plainly on both platforms instead of claiming it away: on Windows the file cannot be deleted while open, and on POSIX unlinking the path while a concurrent acquirer holds the open descriptor creates a split lock domain (a later v1.13-era writer recreates the path on a fresh inode and both believe they hold the lock), bounded in practice by the full-restart instruction. The hold semantics when the root-lock file does not yet exist are stated explicitly (acquiring mints the file, which is then deleted last), and the cross-process test covers both existing and absent root-lock fixtures. Refusal semantics (held by another process, unprovable state) are unchanged.
3. **Coherent, scoped restart boundary.** `restart_required` is reported only when the cutover actually acted: the run removed a sidecar or the stale root lock, or `from_version` predates 1.15; when `from_version` is unknown the rule is fail-safe (treated as pre-1.15, `restart_required` true), and AC-3's rerun-false control therefore uses a fixture with a known post-1.15 `from_version`. Ordinary later upgrades report no cutover restart requirement and keep the established reload flow. Plumbing is named, not implied: `phase_review_evidence_sidecar_cleanup(root)` gains the cutover inputs (its signature currently takes only `root` at `upgrade_wavefoundry.py:1503` with unconditional `restart_required: True` at `:1526`), threaded through all three call paths: the extension seam (`upgrade_extensions.py:528`, where `ctx.from_version` is in hand), the pipeline phase (`upgrade_wavefoundry.py:3202`), and the deferred cleanup call (`:2760`, where `from_version` cannot be recomputed from disk post-extract and must be carried via the upgrade lock state or context). The upgrade surface must stop contradicting itself: the single automatic in-process reload site (`server_impl.py:11533`) fires on both `preflight_to_docs_gate` and `cleanup`, and the cutover runs during `preflight_to_docs_gate`; on a cutover-active run the reload is suppressed at both phases and the reload suggestion (log line at `upgrade_wavefoundry.py:2277` and the `wf_reload_mcp` `next_tools` guidance on upgrade responses) is replaced by the full-restart instruction, with cutover-active detection carried through the machine-readable summary channel (the `review_sidecar_cleanup` counts recorded in the upgrade state); on non-cutover runs the existing reload behavior and guidance are untouched. Named test dispositions: `test_upgrade_wavefoundry.py:4674-4676` (rerun asserts `restart_required` true) is deliberately inverted; `test_upgrade_wavefoundry.py:5463` remains the true-direction control. Reconcile every carrier that states either behavior: seed 160, the rendered upgrade prompt `docs/prompts/upgrade-wavefoundry.prompt.md`, the hand-maintained `docs/prompts/agents/upgrade-wave-context.prompt.md` (cutover restart line), `docs/specs/mcp-tool-surface.md` (including the upgrade-response `next_tools` guidance), `docs/contributing/build-and-verification.md`, `docs/architecture/data-and-control-flow.md` (cutover restart line), `README.md` (upgrade flow line), `docs/references/wavefoundry-overview.md` (upgrade flow line), and upgrade log lines. The 1.15.0 CHANGELOG section gains the cutover and scoped-restart bullets in this wave (commit-message style, no wave IDs) so the most operator-visible carrier states the same rule.
4. **Retire dead inline-ledger compatibility code.** Census every surviving consumer of the inline record parser and its machinery (`validate_review_evidence`'s marker path, `_MARKER_RE`, `_JSONL_FENCE_RE`, the inline branch of `render_review_evidence_records`, the lint/lifecycle `review-evidence-protocol` inline-marker triggers, the dashboard's `inline_marker` consumer in `dashboard_lib.py`, and the bodyless-details/legacy-namespace canonicalization). The census separates detection/rejection from parsing/rendering: the inline-marker fail-closed detection path (`wave_lint_lib/wave_validators.py:989`, `server_impl.py:12528`, rejection at `review_evidence.py:2899-2930`, pinned by `test_docs_lint.py` `test_inline_review_evidence_is_not_a_runtime_fallback`) is a live consumer and a mandatory keep, both because Requirement 6's orphan lint must recognize the legacy marker and because 1.13-era target repositories may hold inline-marker waves forever (seed 209 forbids upgrade from scanning or migrating historical waves, and the migrator was deleted in the cutover). Delete what no live path exercises (the parsing/rendering machinery with no callers). The evidence standard per keep-or-delete verdict is executed and bounded: an in-repo census closed over shipped code (including negative-guard consumers such as the retained-marker and retained-fence rejections at `review_evidence.py:2915` and `:2930`), a released-producer statement of which released packs could have scaffolded inline-form waves, and for field-facing triggers a 1.13-shaped inline-marker fixture run through docs-lint before and after the deletion. No alias, flag, or dormant branch may remain among the deleted set.
5. **Census covers tests; crash cuts terminate for real.** Extend the residue census to `.wavefoundry/framework/scripts/tests/` with per-file bounded allowances for the negative-assertion and probe sites that legitimately carry retired tokens; the allowlist names exact files and stays load-bearing (a dead allowance is a census failure). Add true-termination variants of the named crash cuts: a spawned child process killed via `os._exit` at the cut boundary (before ledger replace; after replace, before projection), with the parent asserting the surviving on-disk state, canonical parseability, and exact-replay convergence. The existing exception-injection cuts remain as fast equivalents; the docs describing the crash matrix state both tiers accurately.
6. **Orphan-ledger lint guard.** A directory in the fixed wave-folder role (`docs/waves/<id-shaped dir>/`) containing a non-empty `events.jsonl` is the orphan state when its sibling `wave.md` is missing, unreadable, or carries neither the source declaration nor the legacy inline marker; docs-lint fails it with an actionable message. The enumeration model is directory-driven (id-shaped directories under `docs/waves/`), not wave.md-file-driven, precisely so the cheaper tamper variant (deleting or renaming `wave.md` while the non-empty ledger survives) is detected rather than walked around; the existing `rglob("*.md")` walk cannot see that state. The check is stateless (tree-only, no receipt or hash) and skips empty ledgers (fresh scaffolds) and non-wave-shaped folders. Predicate sharing is by relocation, not duplication: `_is_canonical_wave_events_path` (currently private to `indexer.py:728`, pure and structural) moves to `review_evidence.py` (a light module `wave_lint_lib/wave_validators.py` already imports; lint must never import `indexer`, which activates the venv at import time), `indexer.py` imports the relocated symbol, and a cross-test pins both consumers to the single definition. Re-word the three boundary-clause carriers (seed 209, `docs/architecture/data-and-control-flow.md`, `docs/contributing/review-and-evals.md`) in this same change, phrased in ledger-surviving terms so the docs match the actual predicate: a surviving non-empty ledger without a readable declared or legacy-marked `wave.md` is a detected state (covering both declaration-line removal and wave.md deletion or rename); the honest undetected boundary narrows to whole-ledger rollback, empty-ledger declaration removal, and co-deletion of ledger plus declaration.

## Scope

**Problem statement:** The events-only authority contract shipped with six unfinished edges: dual prose/typed gate derivation, a lock race in the cutover cleanup, a self-contradicting and unscoped restart boundary, dead inline-compatibility code, verification weaker than its own claims (census excludes tests; crash cuts do not terminate), and an undetected orphaned-ledger state that is cheaply detectable.

**In scope:**

- Gate derivation across all six prose-evidence surfaces (close gate, review implementation phase, review prepare phase, implement Gate 2, transition-policy presence probe, `wf_prepare_wave` readiness council gate) converted to the single authority-resolution facade, typed-exclusive on declared waves; required-lane roster parsing unchanged.
- `phase_review_evidence_sidecar_cleanup` lock-holding rework and its tests.
- `restart_required` scoping, cutover-gated reload-vs-restart behavior and guidance, and all carrier reconciliation.
- Inline-ledger compatibility census and deletion in `review_evidence.py`, lint, and lifecycle triggers.
- Residue census test-scope extension with bounded per-file allowances; true-termination crash-cut tests.
- The orphan-ledger lint check in `wave_lint_lib/wave_validators.py` plus the three boundary-clause carrier re-words and affected test docstrings.
- Focused and full-suite verification; docs lint; census.

**Out of scope:**

- Any receipt, checksum, hash chain, or second authority (unchanged 1tomw prohibition).
- Changing the physical publication-lock pathname or the lock order.
- The review record schema, actionability model, or independence rules.
- Rewriting closed historical wave records.
- Detecting whole-ledger rollback or co-deletion of ledger plus declaration (documented boundary; Git/backups remain the optional history authority).
- The 1.15.0 release itself (separate packaging flow).
