# One-Command Local Bootstrap

## Rationale

New contributors currently follow a long manual setup page: install a language runtime, create a virtual environment, install pinned dependencies, install git hooks, and run the tests. Steps drift out of date and each contributor hits a different failure. A single scripted entry point keeps the steps in one place and lets CI exercise them.

## Product Intent

First-time contributors on native Windows, macOS and Linux go from a fresh clone to a passing local test run with one command, without prior toolchain setup. Before this change, setup took a page of manual steps and often failed.

## Requirements

1. Provide `make bootstrap` as the documented entry point, delegating to `scripts/bootstrap` so the logic lives in one place.
2. The script creates the project virtual environment and installs dependencies from the pinned lockfile.
3. The script installs the pre-commit hooks and runs the fast test suite as its final step.
4. Re-running the script on an already bootstrapped checkout is safe and makes no changes beyond refreshing pinned dependencies.
5. The script prints a short summary of what was installed, where, and the command to run tests again.
6. `CONTRIBUTING.md` and the README quick-start replace the manual steps with the single command.

## Scope

In scope:

- `Makefile` target and `scripts/bootstrap` entry point
- Documentation updates to `CONTRIBUTING.md` and the README quick-start
- A CI job that runs the bootstrap on every pull request

Out of scope:

- Changes to the dependency set or lockfile format
- Editor or IDE configuration
- Container-based development environments

## Acceptance Criteria

- [ ] AC-1: `make bootstrap` exits 0 on the ubuntu-latest and macos-latest CI runners and the fast test suite passes as its last step.
- [ ] AC-2: After the script runs, `pip freeze` in the project environment matches the pinned lockfile exactly.
- [ ] AC-3: A second consecutive run exits 0 and leaves `git status` clean and the environment unchanged.
- [ ] AC-4: The script prints a summary listing the environment path, installed hook names, and the test command.
- [ ] AC-5: `CONTRIBUTING.md` and the README quick-start reference only `make bootstrap`, and the docs link check passes.
- [ ] AC-6: Shell lint (`shellcheck`) and the repository lint job pass on the new files.

## Decision Log

| Decision | Rationale |
| --- | --- |
| Keep `make bootstrap` as a thin wrapper over `scripts/bootstrap` | One implementation, and the Makefile stays discoverable for contributors who already use it |
| Run the fast test suite at the end of bootstrap | Gives contributors immediate confirmation that the environment works |

## Risks

| Risk | Mitigation |
| --- | --- |
| Pinned dependency versions become unavailable | Mirror wheels in the CI cache and fail with a clear message |
| Script behaviour diverges from the docs | The docs reference only the command, not the individual steps |
