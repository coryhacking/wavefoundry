## Rationale

This is track 3 of the [memory-quality arc](../../arcs/244cm%20memory-quality/244cm-arc%20memory-quality.md). The research assessment calls strict admission the best-supported part of the memory design and agent validation its weak link, because the validator can share the author's errors ([assessment](../../arcs/244cm%20memory-quality/research/agent-memory-systems-assessment.md), "Admission: the best-supported part of the design"). It names three cheap hardenings: reject secrets and model-control tokens, flag evidence from untrusted text, and check mechanically that refs resolve before an agent judges. It also asks that rewrites keep their concrete anchor and that an empty briefing be a normal result.

**What admission checks today** (`execution_status: executed`, read and run against the tree on 2026-11-23):

1. `memory_add`, `memory_propose(mode="create")` and `memory_validate` each scan caller text against `wave_lint_lib.constants.MEMORY_DISALLOWED_PATTERNS`, in three copies of the same loop (`wf_server/memory_handlers.py` near lines 584, 990 and 1446). The patterns catch a keyword assignment (`password|passwd|api_key|secret|token` followed by `:` or `=`), "raw transcript" phrasing, routine-log phrasing and personal-fact phrasing. Nothing catches a credential value without a keyword (an `AKIA...` key, a `ghp_...` token, a PEM header) or any model-control token. The lint reuses the same tuple on record files (`wave_lint_lib/wave_validators.py`, `_memory_forbidden_match`).
1. `memory_validate` refuses promote, retain and rewrite when a target of the pending record is missing, through `_memory_file_target_exists` (near line 1350). That check skips `symbol:` refs, never checks evidence refs, never checks `rewrite_targets` or `rewrite_evidence`, and accepts any file whose path ends with the target, found by `root.rglob`. Of 366 target refs on the 174 active records, 78 are bare names or partial paths such as `review_evidence.py` that only this suffix match accepts.
1. `memory_validate` requires `canonical_overlap` in `none|supplements|duplicates` and refuses `duplicates` for promote, retain and rewrite. Nothing asks whether the code at the target already shows the lesson.
1. `memory_validate(verdict="rewrite")` and `memory_add(supersedes=...)` accept any new targets and summary. Nothing keeps the original's anchor.
1. `memory_brief(targets=[...])` puts target-matched records first and then fills the remaining slots with unmatched records (`memory_brief_response`, `matched + unmatched`), pinned by `test_brief_remains_queryless_and_exact_target_promoted`. A targeted briefing is therefore never empty while any active record exists. An empty free-text `memory_search` adds a `no_memory_matches` diagnostic whose recovery tool is `memory_add`, which suggests writing a memory.

**Census of the existing corpus** (`execution_status: executed`, scratch script, read-only): across `docs/`, including every `events.jsonl`, the model-control token patterns in Requirement 3 match 0 lines and the credential patterns match 0 lines. Of about 600 evidence refs on active records, 148 are wave ids, 72 are change ids, 53 are paths with optional line suffixes and 332 are free-form finding slugs, evidence-record ids or test names. No active record cites a URL or a dependency-tree path.

## Product Intent

**Who benefits:** agents that read briefings and validate candidates, and maintainers who run Review memories.

**Before:** a candidate can be promoted when an evidence ref names a deleted file, a wave that does not exist or a line past the end of a file. A credential value or a chat-template control token passes the content scan and, from a proposal, is shown verbatim to the validating agent. A rewrite can drop every target the original had. A briefing for a file no record targets still shows five unrelated records.

**After:** every target and checkable evidence ref is resolved at the current checkout before the agent's judgment is accepted, and an unresolved or ambiguous ref refuses the write with the ref named. Credentials and control tokens are refused by reason, never echoed, and counted by reason. Evidence from a URL or a dependency tree is flagged. A rewrite keeps at least one of the original's resolving targets. A briefing for files no record targets returns nothing, as a normal result.

**First outcome worth delivering alone:** the resolution primitive with its enforcement in `memory_validate` and `memory_add` (AC-1 to AC-3). Track 4 consumes the primitive, so it ships first; the other items depend on nothing but it.

**Boundaries:** admission applies to new writes only. Existing active records are not re-judged or changed (track 4). The query set, the reranker, ranking and indexing are unchanged.

**Intent is established by** AC-2 (an unresolved evidence ref that today's code promotes is refused), AC-8 (a targeted briefing with no match is empty) and AC-11 (the replay measures what the checks would reject and what targeted briefings stop showing). AC-9 proves only delivered guidance; whether validating agents reject code-derivable lessons more often is observed after release through the rejection counts and Review memories outcomes.

## Requirements

1. **Shared resolution primitive.** Add `resolve_memory_refs(root, *, evidence=(), targets=(), tree=None)` to `memory_records.py`, the module that `memory_handlers`, `memory_eval` and the track 4 maintenance check already import. It is deterministic and model-free: it reads only the working tree and the record roots, never Git, the index or the network. "At HEAD" in the arc means the working tree of the current checkout, so a target in an uncommitted new file resolves; the docstring of `resolve_memory_refs` and the memory admission section of `docs/architecture/cross-cutting-concerns.md` state this. Add `memory_ref_tree(root)`, which walks the repository once and returns the reusable file listing a batch caller passes as `tree`. The walk skips `.git/`, `.wavefoundry/` except `.wavefoundry/framework/`, and every directory named `node_modules`, `bower_components`, `vendor`, `third_party`, `site-packages`, `dist-packages`, `.venv`, `venv`, `__pycache__`, `.tox`, `.mypy_cache` or `.pytest_cache`, and it does not descend symlinked directories or Windows junctions (the `contained_files` link checks). Exact-path resolution always reads the disk, so results are the same with and without a supplied `tree`; a bare name that exists only inside a pruned directory is `unresolved`. The primitive returns one entry per ref with `ref`, `role` (`target` or `evidence`), `form`, `state` and, when found, `resolved_path`, plus the lists `blocking` (the admission rule: any ref whose state is `unresolved` or `ambiguous`, and any target whose state is `suffix_only`) and `untrusted` (Requirement 4). A `suffix_only` evidence ref does not block. Callers that judge existing records, such as track 4, read each ref's `state` rather than `blocking`.
   1. **Classification order.** Each ref, with surrounding backticks stripped, is classified by the first rule that applies: (a) a ref that starts with a URI scheme (Requirement 4) is `unchecked` and untrusted, before any path test, so `https://example.com/src/a.py` is never read as a path; (b) `symbol:` and `community:` refs (below); (c) the longest exact-file prefix (next item); (d) for evidence, the wave, change and memory id forms (below); (e) the first-token path form; (f) anything else is `unchecked`.
   1. **Suffix.** A candidate path loses its whole trailing suffix before it is checked: a line `:N`, a line range `:N-M`, a comma line list `:N,M` (two or more items, each `N` or `N-M`), or a chain of one or more `:name` or `::name` segments (where `name` is `[A-Za-z_][A-Za-z0-9_.]*`), so `file.py:symbol`, `test_x.py::test_y` and `path::Class::test` all reduce to the file.
   1. **Longest exact-file prefix.** Split the ref on whitespace. For each prefix of its tokens, longest first, joined with the ref's own whitespace, strip the suffix and test whether what remains is an exact contained file (the `resolved` test below). The first prefix that passes is the path, its suffix is checked, and the remaining tokens are annotation. This keeps `docs/waves/<id> <slug>/wave.md` and `docs/architecture/decisions/<id>-adr <slug>.md` whole, and still resolves the annotated `src/a.py begin_alpha notes` to `src/a.py`.
   1. **First-token path form.** When no prefix is an exact file, fall back to the first whitespace token, strip its suffix, and treat it as a path ref only when it contains `/` or ends in an extension from `memory_records.MEMORY_REF_PATH_EXTENSIONS`: `.py .pyi .md .json .jsonl .toml .yaml .yml .txt .ini .cfg .lock .ps1 .sh .cmd .bat .js .mjs .cjs .ts .tsx .jsx .css .html .sql .java .kt .go .rs .c .h .cpp .hpp .cs .swift .rb .php`. For an evidence ref, anything else is `unchecked`: dotted test ids such as `test_memory_records.MemoryToolTests.test_x`, finding ids, evidence-record ids, slugs and prose. A target is always handled as a path ref at this step unless it is a `symbol:` or `community:` ref, because a target must name a file or a symbol. So the annotated `index_state_store.py begin_build_epoch disjuncts` falls back to `index_state_store.py` and resolves as `suffix_only` to the one walked file with that name. A `:name` or `::name` suffix checks only that the file exists; the name is not resolved. A line, range or list suffix also requires every line to be within the file's line count.
   1. A path ref is `resolved` when that exact repo-relative path is a contained regular file whose on-disk spelling matches case-exactly in every component, and its suffix check passes. It is `suffix_only` when no exact path exists and exactly one walked file ends with `/<ref>`, and `resolved_path` names that file. It is `ambiguous` when several do, and `unresolved` otherwise, including a directory, a line past the end, an escape from the root and a symlink that `contained_files.judge_contained_file` refuses.
   1. A `symbol:NAME` ref is `resolved` when `NAME` occurs as a whole identifier (`\bNAME\b`) in at least one of the same call's file targets that resolved, `unresolved` when there are such targets and none contains it, and `unchecked` when there are none.
   1. An evidence ref is a wave id only when the whole ref matches `[0-9a-z]{5,6}` (the lifecycle prefix grammar in `lifecycle_id`) and contains at least one digit, so five-letter words such as `tests` or `fixed` are `unchecked`, not unresolved wave ids. A wave id is `resolved` when a wave folder with that id exists under the waves root or the configured archive root. A ref shaped `<5 chars>-<kind> <slug>` is a change id when the kind is a change kind and a memory id when it is `mem`; it is `resolved` when a change document, or a memory record body or archive-register entry, with that exact stem exists.
   1. Every other ref, including `community:` targets, URLs, finding slugs, evidence-record ids and test names, is `unchecked`. `unchecked` never blocks.
1. **Enforcement before the judgment is accepted.** Every write path runs the content check of Requirement 3 over every caller field, refs included, before ref resolution, and refuses on a match without resolving anything. Ref resolution runs only on refs that passed it, so a `memory_ref_unresolved` diagnostic that names a ref can never echo a secret. Resolution is checked on the refs of the record that would be admitted. For `promote` and `retain` that is the pending record's own targets and evidence. For `verdict="rewrite"` it is only `rewrite_targets` and `rewrite_evidence`; the pending record's refs are not checked, so a candidate with a gone target can still be rewritten (Requirement 6). For `memory_add`, including `supersedes=...`, it is the new record's refs. `memory_validate` refuses `promote`, `retain` and `rewrite` with a new `memory_ref_unresolved` diagnostic that names each blocking ref and its state, and writes nothing. For a `suffix_only` target the diagnostic suggests the full repo-relative path from `resolved_path`, for example `use src/a.py`; `reject` stays allowed. `_memory_add_response_locked`, the shared write path of `memory_add`, the rewrite and consolidation, refuses the same way before any filesystem write. `_memory_file_target_exists` keeps its name and delegates to the primitive, so a `suffix_only` target no longer passes for a new admission. Existing records are not re-checked or changed. `memory_validate`'s existing `memory_target_not_current` refusal is replaced by `memory_ref_unresolved`. `memory_propose(mode="create")` writes candidates through `create_memory_record`, not the add path, so a draft with a blocking ref is still written as a pending candidate and is checked when it is validated. `memory_propose` dry-run drafts carry each draft's resolution, so the agent sees it before judging.
1. **Content rejection by reason.** One helper, `memory_records.forbidden_content_reasons(fields)`, replaces the three scan loops and returns, per field name, the reason codes that matched. Reason codes and patterns:
   1. `secret`: the existing keyword-assignment pattern, plus new credential shapes in `wave_lint_lib.constants.MEMORY_CREDENTIAL_PATTERNS`: a PEM private-key header (`-----BEGIN [A-Z ]*PRIVATE KEY-----`), an AWS access key id (`\b(?:AKIA|ASIA)[0-9A-Z]{16}\b`), a GitHub token (`\bgh[pousr]_[A-Za-z0-9]{36,}\b` or `\bgithub_pat_[A-Za-z0-9_]{60,}\b`), a Slack token (`\bxox[abprs]-[A-Za-z0-9-]{10,}`), a JWT (`\beyJ[A-Za-z0-9_-]{10,}\.eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}`), an Anthropic key (`\bsk-ant-[A-Za-z0-9_-]{20,}`), an OpenAI project key (`\bsk-proj-[A-Za-z0-9_-]{20,}`), a Google API key (`\bAIza[0-9A-Za-z_-]{35}\b`), a GitLab token (`\bglpat-[A-Za-z0-9_-]{20,}`), an npm token (`\bnpm_[A-Za-z0-9]{36}\b`) and a bearer token, matched case-insensitively (`(?i)\bbearer\s+[A-Za-z0-9._~+/-]{20,}=*`), so `Bearer`, `bearer` and `BEARER` are all caught.
   1. `model_control_token`: new `MEMORY_CONTROL_TOKEN_PATTERNS`: a ChatML-style special token (`<\|[A-Za-z0-9_]{1,32}\|>`, which covers `<|im_start|>`, `<|im_end|>`, `<|endoftext|>` and `<|system|>`), Llama markers (`[INST]`, `[/INST]`, `<<SYS>>`, `<</SYS>>`), Gemma turn markers (`<start_of_turn>`, `<end_of_turn>`), the harness tags `<system-reminder>` and `</system-reminder>`, tool-call markup, opening or closing and with or without a namespace prefix, matched by `</?(?:[A-Za-z][A-Za-z0-9_-]*:)?(?:function_calls|invoke|tool_call|tool_use|tool_result|parameter)\b[^>]*>` (this covers `<function_calls>`, `<invoke name="x">`, `</tool_call>` and namespaced forms such as `<ns:tool_call>`, while `<invoker>` and the word `invoke` do not match), and a line that starts with `Human:`, `Assistant:` or `System:` followed by whitespace. A record that only documents one of these tokens is refused too; that is accepted, and such a lesson names the token in words.
   1. `transcript_or_personal`: the remaining existing patterns, unchanged.
   1. `MEMORY_DISALLOWED_PATTERNS` becomes the union of all three groups. One line checker, `wave_lint_lib.constants.memory_line_reasons(line, exempt_end=None)`, returns the set of reason codes whose patterns match the line, skipping any match whose end offset equals `exempt_end`. The lint passes the end offset of a recognized decision-log source event, which reproduces today's exemption in `_memory_forbidden_match`; the handlers pass `None`; `forbidden_content_reasons` and the record lint (`wave_validators._memory_forbidden_match`, which keeps its prohibition-line exemption) both call it, so reason codes agree everywhere. The handler refusal names fields and reason codes, never the matched text. The lint failure names the record and the reason code and no longer prints the line (today it prints `raw_line.strip()[:80]`). `memory_propose` responses report `rejected_by_reason`, a map from reason code to the number of drafts withheld, and a withheld dry-run draft shows its `source_event` and reasons without its title or summary.
1. **Untrusted evidence flag.** A ref is untrusted when it starts with a URI scheme (`^[A-Za-z][A-Za-z0-9+.-]*://`), or when its path has a component named `node_modules`, `bower_components`, `vendor`, `third_party`, `site-packages`, `dist-packages`, `.venv` or `venv`, or starts with `.wavefoundry/work/` or `.wavefoundry/cache/`. These are the evidence sources that hold text this repository's reviewers did not write: web pages, dependency output and scratch downloads. The flag does not block. It appears as `untrusted_refs` on dry-run drafts and on `memory_add` and `memory_validate` responses, with a `memory_untrusted_evidence` diagnostic telling the validating agent to confirm the lesson against a source in the repository.
1. **Not derivable from the code.** Guidance only, with no new field: the `memory_validate` docstring, `docs/specs/mcp-tool-surface.md`, seed 240 and seed 190 define `canonical_overlap="duplicates"` to include a lesson that the code at the target already shows, in a comment, docstring, assertion or the code itself, so the existing refusal applies.
1. **Rewrites keep the concrete anchor.** An original target "still resolves" when the primitive gives it state `resolved` or `suffix_only`; targets are compared by resolved path. For a `memory_validate` rewrite or a `memory_add(supersedes=...)`:
   1. When at least one original target still resolves, the new targets must include one of them; otherwise the write is refused with `memory_rewrite_anchor_dropped` and nothing changes.
   1. When no original target still resolves, the new targets must all resolve (Requirement 2) and the caller must pass a non-empty, single-line `retarget_reason`; without it the write is refused with `memory_retarget_reason_required` and nothing changes. A new optional `retarget_reason` parameter on `memory_validate` and `memory_add` carries it, and the new record stores it as a `Retarget reason:` line written by the existing `render_memory_record`. The reason passes the content check in Requirement 3. Seed 240 and seed 190 add that a rewrite keeps the path, command, error string or finding it was drawn from and does not condense it into a general lesson.
1. **Empty briefing is normal.** When `targets` is non-empty, `memory_brief` returns only records that match a target and no longer fills slots with unmatched records. An empty result is `status: "ok"` with `advisories: []`, `count: 0` and no diagnostic. A queryless brief with no targets keeps today's policy order. The `no_memory_matches` diagnostic on an empty `memory_search` keeps its code and message but no longer names `memory_add` as a recovery tool.
1. **Measurement.** An evidence script under the wave's `evidence/` folder, run read-only against this repository, records three results in the Progress Log:
   1. the admission replay: every record body in every status run through the primitive, the content helper and the untrusted rule, with counts by reason and by status;
   1. targeted-brief false shows: for every file under `.wavefoundry/framework/scripts/` that no active record targets, the number of advisories `memory_brief(targets=[that file])` returns before and after the change;
   1. the frozen-set control: `wf_memory_eval` held-out production recall@5, precision of the shown set and false-show rate on the same tree before and after the change.
1. **Imports and tests.** Handler code imports framework modules as `import wf_server.X as X`. Tests build temporary corpora and never read or write this repository's memory records.

## Scope

**Problem statement:** agent validation of memory candidates has no mechanical floor for refs, credentials, control tokens, untrusted sources or anchors, and a targeted briefing cannot be empty.

**In scope:**

- The primitive and its enforcement in `memory_validate` and the shared add path (Requirements 1 and 2).
- The content helper and the new pattern groups (Requirement 3).
- The untrusted flag (Requirement 4).
- Guidance for code-derivable lessons and anchor-keeping rewrites in seeds 240 and 190 and both prompt copies of each (Requirements 5 and 6).
- The anchor check (Requirement 6), the targeted brief and the `memory_search` recovery hint (Requirement 7).
- The replay evidence (Requirement 8), tool-surface and architecture docs, and a CHANGELOG entry.

**Out of scope:**

- Re-judging, flagging or changing existing active records; the read-time target check and the audit order. Track 4 (`246to-enh memory-revalidation-by-signal`, wave `249ar`) consumes the primitive for those.
- Changes to `docs/evals/memory-query-set.json` or its lock.
- Reranker thresholds and the retrieval stack, paused by operator decision.
- Indexing and `index_health`.
- Running the full secret scanner (`scan_secrets.py`, 474 rules) at admission; record files stay in that scanner's ordinary coverage after they are written.
- The queryless `session_start` briefing order.

## Platform Behavior

- **Case:** the default file systems on macOS and Windows are case-insensitive, so `Path.is_file()` alone would accept `Src/A.py`. The primitive compares each path component with the directory listing's spelling, so a ref resolves the same way on Windows, macOS, Linux and WSL2 (AC-1). Known limitation: names are compared as stored, without Unicode normalization, so on macOS a ref typed in NFC does not match a file whose name the file system stored in NFD; such a ref is `unresolved`. No tracked path in this repository has a non-ASCII name (`git ls-files`, 2026-11-24).
- **Windows:** refs are written with `/`; the primitive normalizes `\` to `/` before matching and compares POSIX strings. Line counts use universal newlines, so a CRLF checkout gives the same count as LF. Containment and symlink refusal come from `contained_files.judge_contained_file`, which already handles Windows reparse points.
- **WSL2:** behaves as Linux on the Linux file system. On a Windows drive under `/mnt/` the file system is case-insensitive, which the component spelling check covers.
- **Linux and macOS:** no other difference. The primitive starts no subprocess and needs no Git.
- **Line endings:** the change adds no writer. The `Retarget reason:` line is rendered by the existing `render_memory_record`, which the line-ending census already classifies. The primitive, the content helper and the evidence script only read; the evidence script prints JSON to standard output. Existing record writers are unchanged, so the line-ending census needs no new classification.
