# Reword live text: the planning document is a "spec", the durable documents are "behavior contracts"

Change ID: `23myn-change spec-and-behavior-contract-terminology`
Change Status: `implemented`
Owner: Engineering
Status: planned
Last verified: 2026-11-16
Wave: 23lxd spec-names-and-terminology

## Rationale

`23mqu-change spec-lifecycle-names` renames the prompts, phrases and skills and states the vocabulary. If the rest of the text keeps saying "change doc" and keeps calling the `docs/specs/` documents "specs", the framework has two names for the planning document and one name for two different documents. This change brings existing text into line with the decided vocabulary.

## Product Intent

Anyone reading Wavefoundry's prompts, seeds, tool descriptions, messages and guides meets one name for each thing: "spec" for the document that plans a change, "behavior contract" for a durable document under `docs/specs/`. Before: about 800 uses of "change doc" and its variants, about 260 references to the earlier phrases and prompt paths, and an uncounted share of about 1,270 uses of "spec" that mean the durable documents. After: the vocabulary of `23mqu-change spec-lifecycle-names` holds across live text. No identifier, record label, key, code or path changes.

AC-1 and AC-3 together test whether the intent was established.

## Requirements

1. Planning document. Every match of `[Cc]hange[- ][Dd]oc(ument)?s?` at a word boundary in live text is reworded to the matching form of "spec", keeping number and capitalisation. Scale on 2026-11-16: seeds 156 in 32 files, install templates 12, framework README and docs 6, dashboard 1, framework scripts outside tests 160 in 30 files, framework tests 166 in 43 files, `docs/prompts/` 69, `docs/agents/` outside memory 31, `docs/contributing/` 22, `docs/references/` 25, `docs/architecture/` 25, `docs/specs/` 49, root guides 27, rendered host surfaces 25.
2. Phrases and paths. Every live reference to an earlier shortcut phrase or prompt path renamed by `23mqu-change spec-lifecycle-names` uses the new one, except where text is listing the alias. Scale: about 110 in seeds and shipped docs, 27 in scripts outside tests, 123 in tests, 153 in self-hosted docs.
3. Durable documents. Every use of "spec", "specs" or "specification" in live prose that refers to documents under `docs/specs/` is reworded to "behavior contract". The set is found by classifying each occurrence: seeds 223, framework scripts outside tests 484, self-hosted docs 568. Each occurrence falls into one of four classes: the planning document, a behavior contract, a machine-read value, or an unrelated sense (a module spec, a test-directory name, a third-party product name, a Backstage `spec` field). Only the second class is reworded. On first mention in a document the full phrase "behavior contract" is used. The title and prose of seed 230 (the authoring prompt for these documents) and the refresh prompt's mentions of authoring them are in the second class; seed file names are paths and stay.
4. Live text is the tracked repository minus: `docs/waves/`, `docs/agents/memory/`, plan documents under `docs/plans/` other than the plan template, `CHANGELOG.md` entries below Unreleased, the vision documents at the repository root, and `dist/`, `experiments/` and `slides/`.
5. "Change" stays wherever it means the unit of work: admitted changes, a change's status, the changes a wave delivers.
6. A match that is machine-read stays: a path (including `docs/specs/`), a configuration key (including `require_docs_contract_reviewer_for_spec_changes`), a diagnostic code, a lane or role name (including `docs-contract-reviewer`), or a marker string a parser or fixture matches byte-for-byte. Four readers are named because rewording them changes matching in installed repositories or an MCP response value: the earlier-text sides of the legacy-match tables in `review_policy_reconcile.py`, `REVIEW_PLAN_LEGACY_CONTRACT_LINES` and `REVIEW_PLAN_EARLY_CANONICAL_CONTRACT_LINES` in `review_plan_prompt_check.py`, and the `item_type` value `change document` produced in `lifecycle_gate_support.py`. Name history also stays: migration and retired-name tables, the tests that build earlier-named trees and the fixture trees that model an installed repository, the `CHANGELOG.md` Unreleased entries of this wave, and the sentences in seed 160 that narrate which names an earlier rename retired. Instructions in seed 160 that tell an agent which phrase to write are not history and use the current names. Each exception class is listed in the Progress Log with the reader that depends on it. Underscored identifiers are not renamed.
7. Renderer-owned strings follow the same wording, so skills, lifecycle prompt baselines and policy baselines render it under the default profile. Renderer-owned self-hosted surfaces are produced by rendering. Where the renderer replaces only text it recognises as previously shipped (the Guru subagent description), the earlier text is registered as previously shipped so installed repositories receive the new wording.
8. Review-policy carriers are in the set. Before editing them, measure on a scratch copy whether the edit moves the review-policy digest or lapses a recorded readiness approval, and record the result. If it does, the changelog entry states that an upgrade needs one re-Prepare for each readied wave.
9. `CHANGELOG.md` Unreleased records the terminology, states that no identifier, label, key, code or path changed, and notes for distributions that renderer prose changed.
10. The planning-document noun follows the vocabulary profile in the ten strings that composed it from the item noun before this change. `vocabulary_profile` provides one function for it, read at call or render time. Under a profile whose `ITEM_NAME` is the shipped item name it returns "spec" in the requested form. Under any other `ITEM_NAME` it returns the form that string had before this change: "<item> doc", "<item> docs", "<article> <item> doc" with `ITEM_NAME_ARTICLE`, "<item> documents", or the hyphenated "<item>-doc". The shipped item name is a fixed constant, not a profile field. The ten strings are:
    1. In `render_agent_surfaces.py`: the plan skill description, the plan skill gate reminder, the implement-wave gate reminder, the review-plan description, the review-plan body line and the council description.
    2. In `lifecycle_gate_support.py`: the receipt supersession attribution and the prepare council instructions.
    3. In `project_stats.py`: the two labels for missing and unreadable documents.
    4. One addition that did not follow the profile before: the council skill's Boundary line in `render_agent_surfaces.py`, which named the planning document and the container with fixed words, takes both from the profile.

    Under the default profile each of these eleven strings is byte-identical to its text before this requirement was added. No other string that composes a profile noun names the planning document with a fixed word (census of the framework scripts on 2026-11-17). Literal framework prose (tool descriptions, lint and gate messages, seeds, install templates) says "spec" under every profile, as it said "change doc" under every profile before this change; that prose never followed the profile, and this change does not make it. Item and container nouns, record labels, the record filename and prompt names follow the profile as before.
11. The vocabulary statement in seed 001 and in the project overview says that tools, record labels and identifiers are named for the change they track, and that the label shown is the default one. The three sentences that still call the document itself a change ("A spec is one scoped change" in seed 170, the plan prompt and its agent body) say that a spec plans one scoped change, and seed 170's kind note says the retired kind is retired for new changes.

## Scope

**Problem statement:** existing text contradicts the decided vocabulary.

**In scope:**

- Prose, comments, docstrings, MCP tool descriptions, server and lint message text, renderer strings, seeds, install templates, the dashboard string and self-hosted docs.
- Tests whose assertions quote reworded messages, and the tool-handler digest pin for handlers whose description text changes.

**Out of scope:**

- Everything in Requirement 6.
- MCP tool names in prose. The tools are named for the change and stay.
- A reconcile-scan rule reporting the earlier wording in installed repositories.
- Renaming `docs/specs/`, the `docs-contract-reviewer` lane or any configuration key.

**Platforms:** text only. Behaviour is identical on Windows, macOS, Linux and WSL2.
